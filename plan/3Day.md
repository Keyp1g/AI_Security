### 09:00-10:00：整理指令层与信任边界

#### 具体动作

建立下表，并为每行补充“谁可修改、是否可信、泄露会造成什么影响”。

| 层 | 典型职责 | 不应承担的职责 | 主要风险 |
|---|---|---|---|
| System Prompt | 产品总体行为、安全边界、角色 | 存放真实密钥或替代服务端鉴权 | 泄露、被覆盖、策略过宽 |
| Developer Prompt | 应用流程、输出结构、工具策略 | 直接信任外部文档内容 | 配置错误、指令冲突 |
| User Prompt | 用户任务和业务上下文 | 决定自身权限或覆盖安全规则 | 恶意输入、歧义、越权诱导 |
| 外部内容 | 被引用、摘要或检索的数据 | 作为可信控制指令 | 间接指令污染 |

同时写出一个结论：模型内的指令优先级不等于业务权限优先级。即使模型“同意”，服务端仍必须做授权和参数校验。

#### 产出与验收

- 产出：指令层边界表。
- [ ] 每层都写明可修改者和风险。
- [ ] 记录“外部内容是数据，不是控制指令”的原则。
- [ ] 不把厂商产品行为推断为所有模型的通用规范。

### 10:00-11:00：绘制冲突处理与泄露风险图

#### 具体动作

在笔记中绘制以下最小流程，并给箭头补充信任标记：

```text
System / Developer 规则 ----> 组装请求
User 任务 -------------------> 组装请求 -> LLM -> 结构化输出 -> 应用校验
外部文档（不可信数据） -----> 仅作为引用上下文              -> 用户展示
```

设计三种无害冲突：用户要求不同输出格式、外部文本中含“忽略前文”的字符串、任务本身缺少必要信息。记录预期行为分别是保持安全边界、把外部内容视作数据、请求澄清。另列出系统提示泄露的可观测证据：直接复述、结构性摘要、敏感配置字段或内部标识；只在本地模拟文本中验证。

#### 产出与验收

- 产出：流程图与 3 个冲突情景。
- [ ] 图中存在输入、模型、应用校验和展示四个位置。
- [ ] 每个情景都有期望行为和证据字段。
- [ ] 未把模拟字符串用于真实产品的提示词提取。

#### 具体动作

| 组别 | 唯一变化 | 控制项 | 要观察的结果 |
