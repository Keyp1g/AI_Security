## 三、分阶段执行任务

### 阶段 1：阅读安全对齐与越狱概念

#### 具体动作

在 `notes/day-06-jailbreak-basics.md` 用自己的话定义安全对齐、Jailbreak、拒答质量、过度拒答、风险分级。写出限制：安全对齐是分层控制的一部分，模型拒答不能取代应用鉴权、工具拦截和人工审批。

#### 产出与验收

- [x] 概念定义包含边界和可观测行为。
- [x] 明确“安全测试”不等于寻找绕过办法。
- [x] 不复制教材中的攻击字符串或攻击步骤。

### 阶段 2：区分 Jailbreak 与 Prompt Injection

#### 具体动作

建立对照表：Jailbreak 主要关注诱导模型偏离安全行为；Prompt Injection 主要关注不可信输入或外部内容改变应用指令流。比较入口、受害对象、成功证据、应用控制和后续学习阶段。记录两者可能同时出现，但不能因名称相近混为一种漏洞。

#### 产出与验收

- [x] 表格至少有 5 个对比维度。
- [x] 能说明第 8 天才会模拟应用层注入链路。
- [x] 未把模型拒绝误称为系统已安全。

### 阶段 3：建立风险分类和测试矩阵

#### 具体动作

按抽象类别建立矩阵：角色扮演诱导、编码/格式变形、上下文重定向、长上下文、自动化搜索。对每类只记录风险描述、测试目标、允许的抽象输入、预期安全行为、禁止行为；不写可操作 payload。将所有类别映射到三种允许观察：拒答是否明确、是否安全改写、是否保留不该有的敏感信息。

#### 产出与验收

- [x] 每类有允许与禁止边界。
- [x] 测试矩阵不包含可迁移的绕过载荷，只使用虚构标记和抽象代理目标。
- [x] 有“仅授权本地环境”的前置条件。

#### 产出与验收

#### 产出与验收

- [x] 保留 18 条完整原始输出。
- [x] 对拒答、空对象、错误分类和替代帮助质量分别完成人工评价。

#### 产出与验收

- [x] 已完成 5 条正常请求和 6 条灰区请求，共 11 条记录。

- [x] 全部为独立单轮请求，未进行多轮规避尝试。
