### 09:00-10:00：整理 LLM 核心术语

#### 具体动作

| 术语 | 必须回答的问题 | 对安全测试的意义 |
|---|---|---|
| LLM | 它接收什么、生成什么？ | 为什么不能把生成内容当作事实？ |
| Token | 文本为什么不等于模型看到的词？ | 为什么长度、截断和特殊字符会影响测试？ |
| 上下文窗口 | 模型一次能处理的输入输出范围是什么？ | 长输入是否会导致早期指令或证据丢失？ |
| 推理 | 训练完成后如何根据输入生成输出？ | 输出是计算结果还是数据库精确查询？ |
| 预训练 | 模型从海量数据中学习什么？ | 数据质量、版权、隐私和投毒风险在哪里？ |
| 微调 | 为什么要继续训练模型参数？ | 微调数据可能带来偏差、后门和能力变化吗？ |
| 对齐 | 人类偏好如何影响模型行为？ | 拒答、过度拒答和策略绕过如何评估？ |
| 上下文学习 | 不更新参数时，Prompt 如何改变任务表现？ | 示例和上下文是否可能被注入或误导？ |
| 指令微调 | 模型如何学会遵循指令？ | 指令优先级和边界为什么重要？ |
| RLHF | SFT、奖励模型、策略优化分别做什么？ | 安全性是训练目标的一部分，但不是绝对保证。 |

### 10:00-11:00：绘制 LLM 输入到输出流程

#### 具体动作

在 `notes/day-02-llm-basics.md` 中完成一张流程图，必须覆盖：

```text
Prompt
  -> Tokenize
  -> 加载上下文与指令
  -> 模型推理：计算下一个 Token 的概率分布
  -> 解码策略：选择下一个 Token
  -> 重复生成，直到停止条件
  -> Decode
  -> Response
```

为每个步骤补充以下字段：输入、输出、可能的安全问题、可记录证据。例如：

| 步骤 | 说明 | 需要观察的风险 | 可记录证据 |
|---|---|---|---|
| Tokenize | 把文本转换为模型处理的 Token 序列 | 截断、长度超限、边界字符差异 | 输入长度、截断提示 |
| 推理 | 根据上下文预测后续 Token | 幻觉、概率性输出、敏感内容生成 | 完整请求和响应 |
| 解码 | 按参数选择 Token | 非确定性、重复、随机偏差 | temperature、top_p 等参数 |
| Response | 将 Token 还原为文本 | 下游渲染、执行或泄露 | 原始响应、解析结果 |

同时回答：

1. Prompt 是否等于模型内部知识？
2. 为什么同一 Prompt 可能得到不同 Response？
3. 在哪个位置可以加入输入校验、输出过滤和人工审批？

- 产出：流程图和“安全观察点”表。
- [x] 流程图包含计划要求的 5 个固定节点：`Prompt`、`Tokenize`、`模型推理`、`Decode`、`Response`。
- [x] 至少标出输入侧、模型侧、输出侧各一个风险点。
