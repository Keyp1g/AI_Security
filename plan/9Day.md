## 二、资料与边界

阅读教材中 RAG、AI 应用程序层和数据安全相关章节。RAG 实验只使用本地虚构文本，不索引公司文档、个人数据、受版权或访问限制内容。若没有 embedding、向量库或模型，不安装大规模组件作为前置条件，可以先写可验证伪代码和人工检索模拟；必须明确实际能力与待实测项。

## 三、逐小时执行任务

### 08:00-09:00：理解 RAG 组件

#### 具体动作

在 `notes/day-09-rag-architecture.md` 用自己的话解释文档、切分、Embedding、向量库、检索、重排、生成、引用。对每个组件写输入、输出、谁控制它、可能的数据安全风险。特别说明检索到的文本仍是不可信上下文，不能自动提升为指令或事实。

#### 产出与验收

- [ ] 至少 8 个组件有输入和输出。
- [ ] 区分“检索相关”与“内容可信”。
- [ ] 指出权限过滤应在检索前或检索时执行。

### 09:00-10:00：绘制 RAG 数据流与信任边界

#### 具体动作

绘制：`文档接入 -> 来源/权限标记 -> 内容检查 -> 切分 -> 向量化 -> 索引 -> 查询鉴权 -> 检索 -> 重排 -> 上下文组装 -> 生成 -> 引用/输出审查 -> 日志`。标出每一步可投毒、越权、泄露、污染或失效的风险，及可留存的证据。

#### 产出与验收

- [ ] 数据流至少 12 个节点。
- [ ] 每个信任边界有一个控制点。
- [ ] 输出端有引用和审查，而非直接展示。

### 10:00-11:00：准备带标签的本地文档集

#### 具体动作

创建 `labs/rag-security-lab/day-09-dataset-manifest.md`。准备 5 篇干净文档和 5 篇模拟不可信文档，内容均为虚构课程、产品说明或实验规则。每篇写 ID、来源、作者模拟身份、权限标签、创建时间、内容摘要、信任等级、哈希/版本和是否含控制样式文本。不要把不可信文档写成可迁移的攻击指令。

#### 产出与验收

- [x] 10 篇文档都有来源与权限标签。
- [x] 文件不含真实业务内容和敏感数据。
- [x] 不可信文本只用抽象占位模式。

### 11:00-12:00：设计最小 RAG 原型

#### 具体动作

在 `labs/rag-security-lab/day-09-minimal-rag.md` 写最小伪代码或架构：读取已批准文档、按稳定规则切分、建立模拟/实际索引、按用户权限过滤、返回带来源的片段、明确分隔上下文、生成带引用答案、执行输出审查。记录每个函数的输入输出和失败动作。若已有本地工具，可运行一个只含虚构文档的最小原型。

#### 产出与验收

- [x] 原型含权限过滤、来源保留和输出审查。
- [x] 不把生成模型当成鉴权器。
- [x] 本地模型已实测；环境不可用时会明确标记待实测。

### 12:00-13:00：午休

检查文档清单、原型和日志中没有真实文档片段或访问凭据。

### 13:00-14:00：运行/演练最小流程

#### 具体动作

选择 5 个问题，覆盖正确检索、无结果、无权限、相近但错误内容和含不可信文本的结果。运行原型，或进行逐步骤人工演练。保存查询、身份/权限模拟值、候选片段、最终上下文、输出、引用和判定；不能运行的环节标“待实测”。

#### 产出与验收

- [x] 五个问题均有完整过程记录。
- [x] 无权限场景未向最终上下文提供受限片段。
- [x] 引用能指向文档 ID 和版本。

### 14:00-15:00：测试检索污染

#### 具体动作

在不可信文档与干净文档主题相近的前提下，比较检索与生成结果。观察不可信内容是否被召回、是否被标注、是否影响回答范围、是否触发输出审查。记录的是防护行为和残余风险，不尝试提升污染成功率。

#### 产出与验收

- [x] `day-09-retrieval-pollution.md` 有至少 5 组比较。
- [x] 每组有候选片段、来源标签和输出结果。
- [x] 未将模型未受影响解释成全部 RAG 均安全。

### 15:00-16:00：分析防护设计

#### 具体动作

写防护表：文档准入、来源签名/版本、权限元数据、内容隔离、检索过滤、引用约束、输出审查、反馈与索引回滚。每项写攻击前预防、运行时检测、响应动作、日志字段和对应测试 ID。将“外部文本降权”与“确定性权限过滤”分别描述。

#### 产出与验收

- [x] 至少 8 项防护。
- [x] 每项可映射到数据流节点与测试。
- [x] 有索引更新或撤销的响应计划。

### 16:00-17:00：启动作品 2 需求文档

#### 具体动作

创建 `labs/rag-security-lab/requirements.md`：问题定义、非目标、组件、虚构数据集、用户/权限模型、威胁模型、实验用例、日志、验收标准和安全边界。明确阶段一不需要真实向量数据库或真实企业知识库。

#### 产出与验收

- [x] 有功能与安全验收标准。
- [x] 明确输入数据和用户权限模型。
- [x] 有可复测的污染与越权场景。

### 17:00-18:00：复盘与第 10 天准备

#### 具体动作

在 `reports/day-09-review.md` 列出 RAG 最容易忽视的 5 个风险点，并说明今天的原型限制。为第 10 天准备三个模拟工具需求：搜索、受限文件读取、模拟工单创建；均不连接真实服务。

#### 产出与验收

- [x] 五项风险各对应一个数据流节点。
- [x] 区分检索准确率与安全性。
- [x] 三个模拟工具都有输入/输出和禁止动作定义。
