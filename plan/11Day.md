# 第 11 天：LLM 应用层攻击面

> 学习单元：Day 11，共 9 个阶段
> 对应总计划：第 11 天“LLM 应用层攻击面”
> 今日目标：把使用层、应用层、平台层组成一张可检查的攻击面地图，并对一个本地模拟 AI 应用完成端到端威胁建模。

- [x] `labs/day-11-threat-model.md`：一个模拟 AI 客服/RAG/Agent 场景的威胁建模记录。
- [x] `labs/day-11-stride-matrix.md`：STRIDE 风险矩阵和证据要求。
- [x] `AI应用安全检查清单.md`：可交给他人执行的检查清单。
- [x] `reports/day-11-review.md`：三层模型复盘及第 12 天准备。

## 二、资料与环境边界

阅读教材中的 `AI 使用情况层`、`AI 应用程序层`、`AI 平台层`，并回看前几天的 Prompt Injection、RAG、Agent 和输出安全笔记。今天只对本地或明确授权的模拟系统建模；系统中的用户、文档、工具、日志和密钥全部使用虚构占位符。威胁建模的目标是发现控制缺口，不是对真实服务发起探测或利用。

三层模型在本计划中按以下方式使用：

| 层 | 关注对象 | 示例 | 今日要回答的问题 |
|---|---|---|---|
| 使用层 | 人、角色、入口、使用方式 | 聊天界面、API 客户端、管理员操作 | 谁能输入什么、看到什么、触发什么？ |
| 应用层 | Prompt、RAG、Agent、业务逻辑 | 编排服务、检索、工具路由、输出渲染 | 不可信输入如何改变流程或越过业务规则？ |
| 平台层 | 模型、网关、数据、基础设施 | 模型 API、向量库、日志、密钥、队列 | 平台如何隔离租户、保护数据并提供审计？ |

## 三、逐小时执行任务

### 阶段 1：阅读三层架构内容

#### 具体动作

1. 阅读教材对应章节，分别摘录每一层的职责、典型组件和失败后果。
2. 在 `notes/day-11-application-attack-surface.md` 用自己的话解释：三层是分析视角，不是所有产品都严格按此部署；同一风险可能跨越多层。
3. 列出今天建模场景的最小组件：用户界面、身份服务、编排 API、模型、向量库、模拟工具、日志和输出渲染器。
4. 为每个组件写“资产、入口、信任假设、控制者”。

#### 产出与验收

- [x] 三层均有职责、组件和风险说明。
- [x] 明确“分析层次”与“实际部署拓扑”的区别。
- [x] 至少列出 8 个模拟组件及其资产。

### 阶段 2：建立三层攻击面模型

#### 具体动作

绘制一张从使用者到平台的攻击面图，至少包含：用户输入、认证会话、Prompt 组装、外部文档、检索、模型调用、工具调用、输出解析、前端展示、日志和管理配置。对每条边标注数据方向、信任级别、可能的越权点和可记录证据。

在图下回答三个问题：

1. 哪些风险只在模型输出层可见，哪些风险必须由应用或平台控制？
2. Prompt Injection、RAG、Agent、输出安全分别落在哪些层，为什么会跨层？
3. 如果模型输出正常但服务端鉴权缺失，系统是否仍然安全？

#### 产出与验收

- [x] 图包含使用层、应用层、平台层和跨层数据流。
- [x] 每层至少有一个输入风险和一个控制点。
- [x] 明确模型输出不能替代服务端鉴权。

### 阶段 3：映射已学风险到三层

#### 具体动作

在笔记中建立映射表。每个风险至少填写：入口层、受影响资产、跨层路径、成功证据、首要控制和复测方式。

| 风险 | 可能入口 | 受影响资产 | 首要控制 |
|---|---|---|---|
| Prompt Injection | 使用层/外部内容 | 指令边界、工具流程 | 输入来源标记、上下文隔离、输出审查 |
| RAG 污染/越权检索 | 应用层/数据层 | 索引、文档权限、答案引用 | 文档准入、检索时鉴权、来源追踪 |
| Agent 工具滥用 | 应用层 | 外部状态、工具数据 | schema、最小权限、确认、幂等 |
| 不安全输出 | 应用层/使用层 | 浏览器、下游解析器、用户 | 编码、白名单、结构校验 |
| 平台隔离失败 | 平台层 | 模型、租户、日志、密钥 | 租户隔离、密钥托管、访问审计 |

#### 产出与验收

- [x] 至少 5 类风险完成映射。
- [x] 每类风险有证据和复测方式。
- [x] 说明一个风险为什么不能由单层控制单独解决。

### 阶段 4：设计 AI 应用安全检查清单

#### 具体动作

创建 `AI应用安全检查清单.md`，先写清单字段：检查项、适用层、前置条件、验证步骤、期望结果、证据、严重性、修复建议、复测状态。按以下八个域组织项目：身份与权限、输入与 Prompt、RAG 数据、Agent 工具、输出处理、模型与网关、日志与监控、可用性与资源。

每个域至少写 4 项检查，共不少于 32 项。验证步骤只描述合法、无害的配置检查、模拟输入和本地观察，不写针对真实目标的利用步骤。严重性先使用低/中/高三级，并说明判断依据。

#### 产出与验收

- [x] 清单至少 32 项，覆盖八个域。
- [x] 每项都有期望结果和证据形式。
- [x] 检查步骤可在本地模拟环境执行。

### 阶段 5：选择场景并完成资产、角色、边界建模

#### 具体动作

选择一个本地虚构场景，例如“企业内部知识问答助手”：访客可查询公开课程资料，分析员可检索内部模拟文档，管理员可维护索引；Agent 只能调用模拟搜索和模拟工单工具。创建 `labs/day-11-threat-model.md`，写明业务目标、非目标、角色、资产、数据分类、入口、信任边界、允许操作和禁止操作。

至少列出以下资产：用户身份、Prompt 模板、文档内容、向量索引、模型请求、工具参数、工具返回、输出结果、审计日志和配置。为每个资产标记机密性、完整性、可用性和可追溯性要求。

#### 产出与验收

- [x] 场景有业务目标和明确非目标。
- [x] 至少 3 个角色、10 个资产和 5 条信任边界。
- [x] 每个资产有安全属性和责任方。

### 阶段 6：使用 STRIDE 列出威胁

#### 具体动作

创建 `labs/day-11-stride-matrix.md`，按 STRIDE 六类填写威胁：

| 类别 | 在模拟 AI 应用中的问题 | 观察证据 |
|---|---|---|
| 伪造（Spoofing） | 伪造角色、会话或工具调用身份 | 会话主体与请求主体不一致 |
| 篡改（Tampering） | 修改 Prompt、文档、索引或工具参数 | 版本/哈希变化、参数越界 |
| 抵赖（Repudiation） | 调用或配置变更缺少审计 | 无关联 request ID、时间或操作者 |
| 信息泄露（Information Disclosure） | 越权检索、日志暴露、输出泄露 | 受限文档或敏感占位符出现在响应 |
| 拒绝服务（Denial of Service） | 超长输入、重复调用、资源耗尽 | 超时、限额命中、队列堆积 |
| 提权（Elevation of Privilege） | 普通角色触发管理员工具或资源 | 服务端授权拒绝缺失 |

每类至少写 3 个具体威胁、受影响资产、前置条件、影响、检测点、缓解措施和残余风险；风险描述应针对模拟系统的行为，不声称真实漏洞已存在。

#### 产出与验收

- [x] 六类威胁均有至少 3 项。
- [x] 每项都有前置条件、影响、证据和控制。
- [x] 区分威胁假设、已观察现象和待验证项。

### 阶段 7：设计测试方法与证据格式

#### 具体动作

把威胁矩阵转成测试记录模板：`TM-011-xx`、资产、角色、前置条件、输入、执行步骤、期望阻断点、实际观察、证据路径、严重性、修复、复测。为每一类 STRIDE 选择至少一个最小测试：角色边界检查、文档版本校验、日志关联检查、越权检索模拟、超长输入限额、工具权限拒绝。

定义统一证据要求：原始请求/响应、规则版本、模拟身份、时间戳、日志 request ID、文档或工具 ID、截图或文本路径。不得用“没有发现问题”替代具体测试结果。

#### 产出与验收

- [x] 至少 6 个最小测试与 STRIDE 一一对应。
- [x] 证据字段能让他人复测。
- [x] 待实测、通过、失败三种状态定义清楚。

### 阶段 8：完善并发布安全检查清单

#### 具体动作

将威胁建模中的控制点回填到 `AI应用安全检查清单.md`。为每个检查项补充优先级和复测条件，至少加入以下跨层检查：

- 使用层身份与服务端会话是否绑定；
- 应用层是否隔离系统规则、用户输入和外部内容；
- RAG 检索是否在返回片段前执行对象级权限判断；
- Agent 工具是否独立校验 schema、角色和副作用确认；
- 输出是否经过结构化解析、编码和敏感信息检查；
- 平台层是否隔离租户、保护密钥并关联完整日志。

再让清单中的每项都能指向 `TM-011-xx` 或后续实验编号。

#### 产出与验收

- [x] 清单和威胁矩阵之间存在可追踪 ID。
- [x] 至少 6 项跨层检查已写入。
- [x] 复测条件不是泛化的“重新测试”。

### 阶段 9：复盘与第 12 天准备

#### 产出与验收

- [x] 复盘引用至少 5 个本地文件。
- [x] 能解释使用层、应用层、平台层的职责差异。
- [x] 第 12 天准备内容不含真实个人数据或密钥。

## 四、今日不要做的事

- 不把威胁建模假设写成已确认漏洞。
- 不对真实 AI 客服、RAG、Agent 或 API 做扫描、越权测试或压力测试。
- 不使用真实账户、客户文档、密钥、域名和内部架构信息。
- 不以模型拒答、单次测试或清单勾选代替服务端控制证据。
