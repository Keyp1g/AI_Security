# 学习单元 13：AI 安全测试方法论

> 对应总计划：学习单元 13“AI 安全测试方法论”
> 本单元目标：将已有 LLM、Prompt Injection、RAG、Agent 和隐私用例统一为可复测的测试资产，建立风险评分、证据记录与评估报告模板。

## 二、资料与测试边界

阅读教材的“AI红队测试”“AI红队流程”相关内容，并回看学习单元 8-12的用例与实验记录。本单元的工作是方法、记录和评分规范化：仅整理本地或明确授权的模拟环境证据，不新增对真实模型、网站、工具或业务系统的探测。

红队测试的合法前置条件必须写入每次测试：明确授权范围、允许时间、允许资产、禁止动作、数据处理方式、紧急联系人和停止条件。缺少任一关键前置条件时，测试状态应为“未授权/不执行”，而非尝试补足技术路径。

## 三、学习步骤

### 步骤 1：阅读并拆解 AI 红队流程

#### 具体动作

```text
项目方案 -> 授权与范围 -> 团队与职责 -> 威胁建模 -> 测试设计
-> 受控执行 -> 证据保存 -> 风险评分 -> 修复建议 -> 复测 -> 结构化报告
```

分别说明产品负责人、测试人员、应用/平台负责人、数据负责人和复核人的职责。记录 AI 测试与传统测试的额外要求：模型版本和参数、Prompt 版本、上下文来源、非确定性、工具副作用、输出下游处理和数据保留。

### 步骤 2：定义项目范围与测试计划

#### 具体动作

为“本地模拟 LLM 应用”写一个最小测试计划：目标是验证 Prompt 边界、RAG 数据权限、Agent 模拟工具、输出处理和合成数据泄露控制；非目标是攻击真实服务、绕过模型安全策略、访问真实数据或执行外部副作用。

在笔记中填写以下表格：

| 项目 | 内容 |
|---|---|
| 授权资产 | 本地用例、虚构文档、模拟工具、合成敏感字段 |
| 测试角色 | 访客、分析员、管理员模拟身份 |
| 允许动作 | 配置检查、无害输入、模拟权限/格式验证、日志审查 |
| 禁止动作 | 真实外部调用、真实敏感数据、破坏性负载、持久化变更 |
| 成功证据 | 原始请求/响应、规则版本、模拟角色、时间、日志 ID |
| 停止条件 | 超出模拟范围、发现真实秘密、意外外部连接、不可控副作用 |

#### 产出与验收

- [x] 计划明确列出范围、非目标、授权资产和停止条件。
- [x] 允许动作和禁止动作没有重叠。
- [x] 证据要求覆盖模型、应用和工具层。

### 步骤 3：建立统一测试用例字段

#### 具体动作

创建 `cases/llm-security/case-schema.md`，将用例定义为可交给另一位测试者复现的最小单元。固定以下字段：

| 字段 | 要求 |
|---|---|
| ID | 格式 `域-日期-序号`，例如 `LLM-013-01` 或 `AGENT-010-03` |
| 标题与风险类别 | 说明测试对象和风险，不写结论 |
| 范围与授权 | 环境、允许资产、模拟角色、禁止动作 |
| 前置条件 | 规则/Prompt/模型/索引/工具版本与初始状态 |
| 输入与步骤 | 完整无害输入、执行顺序、控制变量 |
| 期望行为 | 可观察、可判定的安全结果 |
| 实际行为 | 原始结果摘要，链接完整证据 |
| 判定 | 通过、失败、待实测、阻断、未授权/不执行 |
| 影响与评分 | 影响资产、四维评分、严重性理由 |
| 证据与复测 | 文件路径、日志 ID、时间、修复版本、复测结果 |

定义状态转换规则：`待实测` 只有在实际执行后才能变为通过或失败；`未授权/不执行` 不计入通过率；`阻断` 表示控制按预期阻止测试动作，但仍需保留证据。

#### 产出与验收

- [x] 用例字段覆盖范围、前置条件、输入、期望、实际、证据、修复和复测。
- [x] 五种状态有清晰、互不混淆的定义。
- [x] 命名规则能避免跨天和跨域 ID 重复。

### 步骤 5：设计风险评分规则

#### 具体动作

在 `labs/unit-13-risk-scoring.md` 定义四个 1-5 分维度，并写出每个维度的评分锚点：

| 维度 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 严重性 | 仅影响单条低敏感模拟输出 | 影响受限模拟资产或业务判断 | 可导致高影响资产/不可逆模拟副作用失控 |
| 可复现性 | 依赖不稳定、未验证条件 | 在固定环境下可重复 | 低门槛、稳定、跨多个模拟请求复现 |
| 影响范围 | 单一测试用例 | 单一应用功能或角色 | 多角色、多组件或共享平台影响 |
| 利用复杂度 | 需要多项特殊前置条件 | 需要已知角色/输入条件 | 常规输入即可触发且无需特殊权限 |

再定义计算与人工复核规则：总分是排序辅助，不自动替代专业判断；涉及权限绕过、敏感信息或副作用时，即使总分较低也须人工复核。记录评分角色、版本、证据和不确定性。

#### 产出与验收

- [x] 四个维度都有 1/3/5 分锚点。
- [x] 有总分使用限制和人工复核条件。
- [x] 分数可以从实际证据回溯，不基于印象。

### 步骤 6：对本阶段样例做批量评分

#### 具体动作

创建 `labs/unit-13-batch-scoring.md`，从学习单元 8-12每类至少选 4 条，共至少 20 条用例进行评分。每条保留 ID、状态、四维分数、总分、严重性等级、评分理由、证据路径和是否需要复核。`待实测` 用例可以预估潜在影响，但必须单列，不能与已观察发现合并统计。

按高到低排序后检查异常：高分但无原始证据、低分但涉及敏感字段、同一发现重复拆分评分、同一根因未关联。修订时记录理由与版本。

#### 产出与验收

- [x] 至少 20 条评分记录，覆盖四类风险。
- [x] 已实测与待实测分开统计。
- [x] 每个高风险项有证据和人工复核标记。

### 步骤 7：编写安全评估报告模板

#### 具体动作

创建 `reports/agent-security-assessment/assessment-template.md`，为作品 5 固定以下章节：

1. 文档控制信息与版本；
2. 摘要与总体风险结论；
3. 测试授权、范围、环境与限制；
4. 架构、资产、角色与信任边界；
5. 方法、用例和评分规则；
6. 发现清单与严重性排序；
7. 每项发现的证据、影响、根因、修复和复测；
8. 未验证项、残余风险和后续计划；
9. 附录：用例 ID、日志/证据索引、术语表。

在每项发现模板中强制要求“观察事实”“风险推断”“限制”三个小节，防止将猜测写成漏洞结论。报告中使用虚构系统名和占位符，不能填入真实客户或目标。

#### 产出与验收

- [x] 模板包含范围、证据、发现、修复和复测。
- [x] 每项发现区分事实、推断和限制。
- [x] 有文档版本和审阅人字段。

## 四、本单元禁止事项

- 不对真实目标开展红队测试、扫描、越权验证或自动化攻击。
- 不在没有授权、范围和停止条件时执行测试。
- 不用风险总分替代人工判断，或掩盖高影响低频风险。
- 不把待实测、阻断或未授权状态写成“通过”。
- 不将真实敏感数据放入用例、证据、截图或报告模板。
