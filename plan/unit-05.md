# 学习单元 5：Prompt 工程流程化

> 对应总计划：学习单元 5“Prompt 工程流程化”
> 本单元目标：将前两天的观察沉淀成可复用、可评估、可复测的 Prompt 工作流与模板。

## 一、本单元完成标准

- [x] `notes/unit-05-prompt-workflow.md`：工作流、模板字段与评估指标。
- [x] `labs/unit-05-template-evaluation.md`：四类任务各三条测试输入及两轮结果。
- [x] `cases/llm-security/prompt_templates.md`：分析、生成、审计、报告四类可复测模板。
- [x] `reports/unit-05-review.md`：流程图、失败点和学习单元 6 准备。

## 二、资料与边界

阅读教材的“设计前的准备”“Prompt框架”“prompt优化与迭代”“Prompt自查清单”。模板仅用于低风险、模拟任务；“审计”模板只分析虚构接口描述或本地代码片段，不能输出针对未授权目标的攻击指令。模板不承载身份鉴别、工具授权或敏感数据处理规则。

## 三、学习步骤

### 步骤 1：提取流程要素

#### 具体动作

阅读上述小节，在 `notes/unit-05-prompt-workflow.md` 中列出设计前必须确认的内容：任务目的、用户、已知事实、允许数据、风险边界、输出消费者和失败处理。标出学习单元 3 的指令边界与学习单元 4 的事实核查在哪个环节进入。

#### 产出与验收

- [x] 至少 7 个设计前问题。
- [x] 每个问题都能影响 Prompt 或应用设计决策。
- [x] 有数据最小化和事实核验项目。

### 步骤 2：建立标准工作流

#### 具体动作

建立并解释流程：`明确目标 -> 选择必要上下文 -> 写明约束 -> 定义输出格式 -> 预演失败 -> 运行测试 -> 评估与修订 -> 版本化保存`。为每一步写输入、输出、负责人、失败信号和下一步；将权限和敏感操作标为“应用层控制”，不能交给模型自行裁定。

#### 产出与验收

- [x] 工作流含 8 个步骤。
- [x] 至少两个失败信号能触发重试、拒绝或人工复核。
- [x] 有 Prompt 版本号和变更原因记录要求。

### 步骤 3：制作四类模板

#### 具体动作

在 `cases/llm-security/prompt_templates.md` 写四个模板，均保留占位符而非真实数据：

| 类型 | 目的 | 强制字段 | 特有安全要求 |
|---|---|---|---|
| 分析 | 解释给定材料 | 目标、材料、范围、证据 | 区分事实与推断 |
| 生成 | 生成草稿 | 受众、内容、格式、禁项 | 禁止捏造来源 |
| 审计 | 审查模拟需求 | 范围、资产、证据、输出 | 不输出未授权利用步骤 |
| 报告 | 汇总测试结果 | 发现、证据、影响、限制 | 未证实项显式标记 |

每个模板有目标、上下文、约束、输出 schema、验收规则、失败处理、版本字段。

#### 产出与验收

- [x] 四类模板字段完整。
- [x] 模板能复制后直接填入虚构任务。
- [x] 每个模板有至少一条安全边界。

### 步骤 4：准备测试集

#### 具体动作

为四类任务各准备 3 条输入，共 12 条。设计至少一条正常、缺少关键资料、格式冲突的输入；所有任务使用模拟课程、虚构系统和本地资料。建立测试表：模板版本、用例 ID、输入、期望、实际、相关性、完整性、可执行性、安全性、备注。

#### 产出与验收

- [x] 12 条输入覆盖四类任务。
- [x] 每条有明确验收条件。
- [x] 不包含真实生产资产和个人信息。

### 休息步骤：午休

下午开始前检查模板中的占位符没有被误替换成敏感内容。

### 步骤 5：第一轮模板执行

#### 具体动作

对 12 条输入运行第一轮，或在无模型时登记待实测。保留完整原始输出，对每条按 1-5 分评价相关性、完整性、可执行性、安全性，并写明评分证据。输出不能通过 schema、违反禁项或捏造来源时明确记录失败类型。

#### 产出与验收

- [x] 12 条都有结果或待实测状态。
- [x] 评分附具体证据，不只给总分。
- [x] 原始输出保留在实验记录中。

### 步骤 6：使用自查清单迭代

#### 具体动作

对失败或低分样例仅修改一个可解释点，例如补充受众、规定字段、删除无关背景或增加来源限制。版本号从 `v0.1` 升至 `v0.2`，记录变更、假设和结果。不要为了追求分数删除安全边界或把失败用例排除在统计外。

#### 产出与验收

- [x] 至少 4 条样例有前后版本对比。
- [x] 每次只说明一个主要修改。
- [x] 记录未改善或恶化的结果。

### 步骤 7：固化评估指标

#### 具体动作

为相关性、完整性、可执行性、安全性各定义 1/3/5 分锚点。补充硬性门槛：泄露敏感字段、虚构关键来源、输出不可解析或越过范围时不能以平均分掩盖。写明人工复核条件。

#### 产出与验收

- [x] 四项指标均可由他人重复打分。
- [x] 有硬性失败门槛与人工复核条件。
- [x] 指标不将“内容更长”误判为“更完整”。

### 步骤 8：合入作品 1

#### 具体动作

整理四个模板、12 条测试记录和判定规则到 `cases/llm-security/prompt_templates.md`。每类选择至少一条失败样例，写出模板改进建议和复测状态，保持与前几日用例相同字段。

#### 产出与验收

- [x] 四种任务都有模板、测试和判定。
- [x] 每条模板可追溯版本。
- [x] 未把模型评分作为唯一质量结论。

### 步骤 9：复盘与准备学习单元 6

#### 具体动作

在 `reports/unit-05-review.md` 画出“想法到可测样例”流程图，写明最有效与最无效的改动、指标限制和下一单元的合规越狱防护测试边界。附 4 个以上本地证据路径。

#### 产出与验收

- [x] 流程图涵盖目标、约束、测试、评估、迭代。
- [x] 能解释为什么模板不能保证安全。
- [x] 学习单元 6 只验证拒答、澄清和安全替代能力。

## 四、本单元禁止事项

- 不把模板当作鉴权、脱敏或安全过滤器的替代品。
- 不使用模板请求真实系统的漏洞利用、凭据或内部数据。
- 不删除失败结果以获得更高平均评分。
- 不在无证据时声称 Prompt 已“防住”注入或越狱。
