# 学习单元 8：Prompt Injection 入门

> 阶段：学习单元 8
> 对应总计划：学习单元 8“Prompt Injection 入门”
> 本单元目标：理解不可信内容如何改变 LLM 应用行为，在本地模拟系统中测试并记录指令边界、输出与数据保护控制。

## 一、本单元完成标准

- [x] `notes/unit-08-prompt-injection.md`：攻击面、信任边界与控制清单。
- [x] `labs/unit-08-direct-injection.md`：本地模拟问答流程记录。
- [x] `labs/unit-08-indirect-injection.md`：本地模拟文档摘要流程记录。
- [x] `cases/llm-security/prompt_injection_cases.md`：至少 20 条防护验证用例。
- [x] `reports/unit-08-review.md`：攻击面复盘与学习单元 9 准备。

## 二、资料与安全边界

阅读教材 `Prompt注入` 相关章节。实验目标是验证防护而非突破第三方系统：只使用本地模拟系统、虚构 system/developer 文本、虚构文档和无敏感输出。不要向公开模型、浏览器插件、企业机器人或外部网页提交注入内容；不要请求或输出密钥、账户、私有文档、隐藏提示或任何数据外带操作。

## 三、学习步骤

### 步骤 1：学习并区分注入类型

#### 具体动作

在 `notes/unit-08-prompt-injection.md` 定义直接注入、间接注入、系统提示泄露诱导和工具指令污染。以“攻击者控制的内容被模型误当成高优先级指令”为核心机制，分别写来源、受影响资产、可观察成功信号和主要防护；注明学习单元 6 Jailbreak 更关注模型对齐偏离，而本单元重点是应用信任边界。

#### 产出与验收

- [x] 四类均有来源、影响和防护。
- [x] 能说明为什么内容过滤不是唯一控制。
- [x] 不记录可直接复用的攻击提示词。

### 步骤 2：绘制应用链路与信任边界

#### 具体动作

绘制：`用户输入 + 应用规则 + 外部文档 + 工具返回 -> 提示组装 -> LLM -> 输出解析 -> 权限校验 -> 展示/执行`。为每个节点标注可信度、可控者、可记录日志和失败后的阻断点。特别标注：外部文本、网页、邮件、检索片段和工具结果都应被视为数据；模型输出不可直接执行。

#### 产出与验收

- [x] 至少 7 个节点与 4 条信任边界。
- [x] 有输入、输出、工具三类防护点。
- [x] 明确服务端授权在模型之后独立执行。

### 步骤 3：设计防护验证用例

#### 具体动作

在 `cases/llm-security/prompt_injection_cases.md` 准备 20 条 `LLM-008-xx` 测试用例：5 条用户输入冲突、5 条外部文本含无害控制样式字符串、4 条格式突破尝试、3 条模拟敏感占位数据诱导、3 条工具返回污染。输入只使用固定占位词，例如 `[UNTRUSTED_TEXT]`、`[SIMULATED_SECRET]`；期望是保持任务范围、把外部内容当数据、拒绝泄露占位数据、输出可解析的安全结果。

#### 产出与验收

- [x] 20 条均有前置条件、输入、期望、判定和证据字段。
- [x] 没有真实密钥或真实提示内容。
- [x] 成功/失败标准可由他人复测。

### 步骤 4：搭建本地模拟链路

#### 具体动作

在实验文档中描述最小模拟系统，不要求接入真实模型：固定应用规则、用户输入槽、外部文档槽、模拟工具返回槽、模型输出槽、日志槽。可以用伪代码或手工拼接示例。定义日志至少记录输入来源标签、规则版本、组装结果哈希、输出、阻断原因和时间；日志不记录真实敏感值。

#### 产出与验收

- [x] 组件和数据流可由他人照文档复建。
- [x] 外部内容带明确 `untrusted` 标签。
- [x] 有输出解析与阻断位置。

### 休息步骤：午休

不安排任务。确认模拟环境没有外网目标、真实凭据和真实业务文件。

### 步骤 5：测试直接注入防护

#### 具体动作

在本地模拟问答流程中运行 10 条用户输入冲突用例。记录规则是否保留、任务是否被转移、输出是否包含模拟敏感占位符、应用是否在输出不符合 schema 时阻断。没有可用模型时，记录组装后的输入和预期阻断逻辑为待实测，不伪造模型行为。

#### 产出与验收

- [x] `labs/unit-08-direct-injection.md` 有 10 条记录或待实测项。
- [x] 每条含来源、组装规则版本、原始输出/待实测、判定。
- [x] 不测试外部系统。

### 步骤 6：测试间接注入防护

#### 具体动作

在文档摘要模拟流程中，将 10 条虚构文档标为可信内容或不可信引用，其中不可信文档含无害控制样式字符串。观察摘要是否把该字符串当作数据、是否正确保留文档来源、是否要求应用层过滤或降权。记录检索内容与控制指令的分隔效果。

#### 产出与验收

- [x] `labs/unit-08-indirect-injection.md` 有 10 条记录或待实测项。
- [x] 文档来源与信任级别在记录中可见。
- [x] 不从互联网抓取不受控内容作为实验输入。

### 步骤 7：建立检测与防护清单

#### 具体动作

按输入源、指令边界、敏感输出、外部内容降权、结构化解析、服务端授权、日志审计、人工升级建立检查清单。每项写检测信号、阻断动作、残余风险和复测用例 ID。强调不依赖单一关键词过滤，也不接受模型自行授予权限。

#### 产出与验收

- [x] 至少 8 项可测试控制。
- [x] 每项关联一个用例或日志字段。
- [x] 有至少 2 项模型外控制。

### 步骤 8：整理作品 1 用例库

#### 具体动作

审查 20 条用例的字段统一性，补充修复建议和复测结果。按直接/间接、输入/文档/工具来源给用例打标签；对“待实测”保持该状态，不能因为设计良好就判定通过。

#### 产出与验收

- [x] 20 条用例编号唯一、标签清晰。
- [x] 每条有实际状态与证据位置。
- [x] 修复建议包含应用层控制。

### 步骤 9：复盘与学习单元 9 准备

#### 具体动作

创建 `reports/unit-08-review.md`，解释 Prompt Injection 从哪些输入源进入、哪些控制在模型外、本单元的模拟范围和限制。为下一单元准备 5 篇干净文档和 5 篇模拟不可信文档，均使用本地虚构内容并注明来源。

#### 产出与验收

- [x] 复盘引用至少 4 个本地文件。
- [x] 能解释“文档是数据，不是指令”。
- [x] 学习单元 9 资料集的来源标签已定义。

## 四、本单元禁止事项

- 不向第三方服务投递注入文本或探测隐藏提示。
- 不请求、收集或展示真实敏感信息。
- 不允许模型输出直接触发工具、网络或文件操作。
- 不把单次未受影响结果称为防护完成。
