## 二、资料与实验边界

阅读教材 `## 大模型使用过程常见踩坑点`（约第 1376 行）及相关隐私、资源消耗内容。今天的幻觉题目必须使用可验证的公开基础事实或明确虚构事实；偏见测试使用中性、假设性的角色描述，不对真实个人或受保护群体作能力、价值或风险判断。模型输出不是事实来源，也不作为招聘、信贷、医疗、法律或执法决定依据。

## 三、逐小时执行任务

### 08:00-09:00：识别常见失败模式

#### 具体动作

阅读教材后，在 `notes/day-04-hallucination-bias.md` 分别定义：事实幻觉、引用幻觉、知识滞后、过度自信、模型偏见、过度依赖、资源消耗和隐私风险。每个定义写出触发条件、用户影响、可见证据、不能仅凭什么判断。

#### 产出与验收

- [x] 至少 8 类风险，每类有触发条件和证据。
- [x] 区分“模型不知道”与“模型无依据地编造”。
- [x] 不把任何群体特征当作事实结论。

### 09:00-10:00：设计事实核查流程

#### 具体动作

建立如下流程并为每步写责任人和证据位置：

```text
拆分声明 -> 标记可核查项 -> 查找一手/权威来源 -> 第二来源交叉验证
-> 标注已证实、未证实、冲突 -> 决定引用、降级回答或人工复核
```

准备一张记录表：声明、模型原话、来源 URL/本地资料、核验结果、时间、复核人、后续动作。若无法可靠核验，结果必须是“未证实”，不能用模型语气强弱代替验证。

#### 产出与验收

- [x] 流程包含来源检查、交叉验证和不确定性标注。
- [x] 表格能追溯模型原始说法和核验依据。
- [x] 明确高影响场景需要人工复核。

### 10:00-11:00：建立可信度与展示规则

#### 具体动作

为答案设计 `可核验`、`待核验`、`不应回答` 三种展示状态。列出不能由模型单独决定的事项：高影响决策、敏感个人资料、实时政策、法律医疗结论、外部操作命令。再写一个引用规则：引用必须可打开、与声明相关、能定位到原始内容；不存在或无法核验的引用不能展示为事实。

#### 产出与验收

- [x] 三种状态各有触发条件和展示动作。
- [x] 说明置信度分数不等于真实性。
- [x] 规则可用于后续 RAG 输出审查。

### 11:00-12:00：准备 15 条测试问题

#### 具体动作

创建 `cases/llm-security/day-04-hallucination-bias.md`。准备 10 条幻觉测试：虚构法规、虚构机构、错误前提、过期信息、不可得引用、数字计算和上下文矛盾。准备 5 条公平性测试：在保持任务条件相同的情况下替换中性身份描述，观察是否出现无依据的差别结论。每条使用 `LLM-004-xx`、测试目的、输入、期望安全行为、证据和判定字段。

#### 产出与验收

- [x] 15 条都可在本地/授权模型复测。
- [x] 偏见用例没有要求模型评判真实群体优劣。
- [x] 每条注明“编造”“承认不确定”“请求澄清”等可观察判定。

### 12:00-13:00：午休

不安排任务。检查测试样例中没有个人资料、真实 API Key 或高影响业务请求。

### 13:00-14:00：测试幻觉与纠错行为

#### 具体动作

运行幻觉样例，记录模型是否：编造细节、说明无法确认、请求来源、给出可验证引用、在被指出矛盾后修正。对每次结果保存完整 Prompt 与原始 Response。对“事实正确”也记录来源，而不是仅凭印象判定。

#### 产出与验收

- [x] 至少 10 条运行记录或待实测记录。
- [x] 每条结论都附核验状态。
- [x] 未将一次正确回答当作模型可靠性的证明。

### 14:00-15:00：测试公平性与安全改写

#### 具体动作

对五对语义相同的中性任务，只替换不影响任务的身份措辞，比较评分、建议、语气和拒答差异。出现差异时，先排除 Prompt 语义变化和随机输出，再记录为“需复核的差异”。将不恰当的概括改写成基于明确、相关、可验证条件的建议。

#### 产出与验收

- [x] 每对测试保留两个完整输入和输出。
- [x] 不把小样本差异宣布为训练数据偏见结论。
- [x] 至少写出一种安全改写策略。
