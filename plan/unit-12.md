# 学习单元 12：训练数据泄露与隐私风险

> 对应总计划：学习单元 12“训练数据泄露与隐私风险”
> 本单元目标：区分训练、上下文、日志和工具返回四类泄露面，用虚构敏感样例验证检测、脱敏、访问控制和保留周期设计。

- [x] `reports/unit-12-review.md`：完成“训练数据泄露不等于提示词泄露”复盘。

## 二、资料与环境边界

阅读教材中的“隐私窃取、成员推理、模型反演、敏感信息泄漏”相关内容。本单元不收集、输入或输出真实个人信息、真实 API Key、客户资料、内部文档或真实训练数据；所有样例使用明显无效的占位值，例如 `user01@example.invalid`、`13800000000`、`sk-test-FAKE-ONLY`。这些字符串只用于检测规则验证，不代表真实凭据。

注意四种概念边界：训练数据泄露关注模型参数或训练语料可能复现的信息；上下文泄露关注当前请求携带的内容；日志泄露关注系统保存或展示的请求、响应和元数据；工具返回泄露关注外部工具把敏感字段带回模型或用户。仅凭模型复述一次内容，不能证明它来自训练数据。

## 三、学习步骤

### 步骤 1：阅读隐私风险概念

#### 具体动作

在 `notes/unit-12-privacy-risks.md` 用自己的话定义训练数据泄露、成员推理、模型反演、上下文泄露、日志泄露、工具返回泄露、脱敏、数据最小化和保留周期。每项写触发条件、可观测证据、需要的额外验证和不能直接下的结论。

#### 产出与验收

- [x] 至少 9 个术语都有定义和安全意义。
- [x] 明确模型复述上下文不等于训练数据泄露。
- [x] 区分“风险信号”“已证实泄露”和“待进一步验证”。

### 步骤 2：区分四类泄露面

#### 具体动作

建立对照表，至少包含数据来源、发生阶段、典型证据、责任组件、首要控制和复测方式。使用同一虚构字段分别模拟放入 Prompt、日志、工具响应和预训练语料说明中，比较测试目标，避免把不同问题混在一条用例里。

| 泄露面 | 发生阶段 | 重点验证 | 首要控制 |
|---|---|---|---|
| 训练数据 | 训练/推理 | 是否可能复现或推断训练样本 | 数据治理、去重、隐私评估 |
| 上下文 | 请求组装/输出 | 模型是否复述当前输入中的敏感字段 | 输入脱敏、最小化、输出审查 |
| 日志 | 记录/调试/监控 | 敏感字段是否进入日志或错误页面 | 日志脱敏、访问控制、保留周期 |
| 工具返回 | 工具执行/观察 | 工具是否把不必要字段带回模型或用户 | 字段最小化、权限、响应过滤 |

#### 产出与验收

- [x] 四类差异至少有 6 个比较维度。
- [x] 每类都指定了责任组件和证据。
- [x] 没有声称可通过单次 Prompt 证明训练数据泄露。

### 步骤 3：绘制数据生命周期

#### 具体动作

绘制并标注控制点：

```text
采集 -> 清洗/脱敏 -> 训练或微调 -> 索引/缓存 -> 推理上下文
-> 工具/应用处理 -> 日志/监控 -> 反馈与删除/保留
```

为每一阶段写数据类别、允许访问者、敏感字段是否必要、访问证据、删除或撤销动作。特别标出索引、缓存、错误日志和人工反馈容易被遗漏的位置。使用数据流图中的编号（D-01 等）关联后续用例。

#### 产出与验收

- [x] 至少 8 个生命周期节点。
- [x] 每个节点都有一个隐私控制或待验证点。
- [x] 说明数据删除如何传播到缓存、索引和日志。

### 步骤 4：准备虚构敏感样例

#### 具体动作

创建 `labs/unit-12-synthetic-secrets.md`，准备四类各至少 5 条样例：邮箱、手机号、API Key 形态、业务敏感字段（如虚构订单号、内部标签、模拟患者编号）。每条写 `sample_id`、原始占位值、类型、是否应脱敏、允许展示范围、替换值、测试位置和销毁说明。

样例必须使用 `.invalid` 域名、明显假的密钥前缀或保留号段；业务字段不得对应真实机构或个人。文档中禁止粘贴从历史日志、聊天记录或代码仓库找到的真实秘密。

#### 产出与验收

- [x] 至少 20 条合成样例。
- [x] 每条都有类型、处理规则和允许范围。
- [x] 能证明样例不是真实凭据或个人信息。

### 休息步骤：午休

不安排学习任务。检查上午文件、终端历史和临时输出中没有真实敏感信息；若误放入，立即删除并记录处理，不继续传播。

### 步骤 5：设计敏感信息检测规则

#### 具体动作

创建 `labs/unit-12-detection-rules.md`，分别设计：

1. 正则规则：邮箱、手机号、模拟 Key 前缀、订单/工单编号；
2. 关键词规则：`internal`、`confidential`、`patient_id` 等虚构标签；
3. 上下文规则：字段名与值组合、脱敏前后关系、允许展示角色。

每条规则写 ID、输入、预期命中、误报例子、漏报风险、处理动作和版本。规则只做检测与脱敏验证，不直接修改原始证据；原始证据应安全保存或使用哈希/占位符。

#### 产出与验收

- [x] 三类规则均有正例、负例和限制。
- [x] 至少记录 3 个误报或漏报风险。
- [x] 处理动作包括告警、遮盖、阻断和人工复核。

### 步骤 6：测试上下文和工具返回复述

至少完成 8 条上下文测试和 4 条工具返回测试；没有可用模型时标“待实测”，不能编造 Response。

#### 产出与验收
