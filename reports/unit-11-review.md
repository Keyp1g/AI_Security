# 学习单元 11：LLM 应用层攻击面复盘

> 完成范围：三层攻击面、风险映射、虚构企业知识助手威胁模型、STRIDE、证据模板、32 项检查清单和平台服务器案例同步。
> 结论边界：多数应用风险是离线威胁建模和待实测测试设计；只有明确引用服务器案例/runbook 的平台控制属于服务器实测。

## 1. 本单元结论

三层模型的价值不是把系统机械分成三个部署区，而是帮助定位责任：

- 使用层说明谁在操作、从什么入口输入、能看到什么以及人如何使用结果。
- 应用层说明 Prompt、RAG、Agent、输出解析和业务规则如何组合，并负责把不可信模型输出变成受控候选。
- 平台层负责身份、模型网关、索引、工具执行、密钥、租户隔离、配额和审计等强制边界。

安全结论不能只看模型是否拒答。模型输出正常时，上游仍可能已经越权读取；模型输出危险时，平台授权仍应保证副作用为零。

## 2. 四类风险如何跨层

### Prompt Injection

入口可能是使用层用户输入，也可能是应用层摄入的文档、记忆或工具结果。应用层负责来源标记、上下文分区、任务约束和候选动作校验；平台层必须对工具和对象强制授权。只做关键词过滤不能阻止语义变体和间接注入。

### RAG

应用层决定文档接入、检索、重排、上下文和引用策略，平台层承载索引、缓存、元数据与租户范围，使用层最终看到答案和引用。相关性、访问权限和来源可信度必须分别判断；无权正文应在模型调用前阻断。

### Agent

模型和规划器只提出候选动作。应用层执行 allowlist、Schema 和业务策略，平台工具网关与业务 API 对主体、动作、对象和参数再次授权，并处理确认、幂等和审计。合法 JSON 只代表结构有效。

### 输出安全

应用层负责结构解析、字段白名单、编码、敏感信息和引用审查；使用层负责安全展示和人工复核；平台层保存最小审计证据。流畅文本、漂亮引用或模型自报置信度不能替代事实证据和授权。

## 3. STRIDE 中最重要的三个风险

1. **信息泄露：无权文档进入上下文或输出。** 一旦正文在授权前进入模型，后置输出过滤很难证明数据没有被处理、缓存或写入日志。首要控制是模型前对象/租户 ACL 和最终上下文白名单。
2. **提权：普通角色触发高权限工具或参数。** Prompt、记忆、工具返回和模型 JSON 都可能提出越权动作。首要控制是主体×工具×动作×对象×参数授权、可信确认和业务 API 兜底。
3. **篡改：Prompt、文档 ACL、索引或工具参数被修改。** 完整性失效会改变后续所有判断。首要控制是服务端元数据、版本/哈希、审批、授权绑定参数摘要和可回滚审计。

可用性风险也很重要：超长上下文、Agent 循环、重试风暴和日志增长需要预算、超时、幂等、队列上限与轮转共同控制。

## 5. 模拟环境限制

- 架构是虚构的知识助手，未连接真实 IAM、业务 API、浏览器渲染器或生产模型网关。
- 大部分控制通过文档、旧实验和确定性模拟器设计，未形成统一端到端运行环境。
- 严重性是本单元低/中/高初判，尚未结合真实业务影响、数据分类、暴露范围和可利用性重新评分。
- 服务器平台证据与本地应用模型属于不同环境，只能作为平台控制案例，不能替代应用测试。

## 7. 学习单元 12 脱敏样例准备

以下数据全部为虚构格式，仅用于比较 Prompt、普通日志和工具返回三个泄露面：

| 类型 | 虚构样例 | 预期处理 |
|---|---|---|
| 邮箱 | `user.alpha@example.invalid` | 非必要时遮盖为 `u***@example.invalid` |
| 手机号 | `13800000000` | 展示为 `138****0000` |
| API Key 形态 | `sk-test-7F3A91-DO-NOT-USE` | 响应和普通日志中完整阻断 |
| 客户 ID | `CUST-DEMO-0042` | 仅授权角色可见；日志保存哈希/引用 |
| 订单 ID | `ORDER-DEMO-1007` | 与服务端主体/租户绑定 |
| 内部标签 | `CLASS-INTERNAL-DEMO` | 不向 visitor 展示 |
| Canary | `AISEC_CANARY_unit12_7F3A91` | 用于检测跨边界泄露，不作为真实秘密 |

比较计划：

- Prompt 面：检查最小上下文、字段授权和模型响应。
- 日志面：检查普通日志是否只保存类型、哈希和证据引用。
- 工具返回面：检查返回 Schema、字段白名单、信任标签和下一轮候选调用。
