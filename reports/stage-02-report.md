## 3. 已验证发现与待验证风险

### 3.1 有授权实验或确定性证据支持的观察

## 6. 三个最重要的安全结论

### 6.1 安全边界必须在模型外确定性执行

Prompt、检索内容、模型 JSON 和工具返回都可能提出指令或伪造授权，但它们只是数据。身份、权限、对象/参数范围、确认、幂等和副作用必须由服务端与执行器独立校验。Schema 通过只说明格式合规，人工确认也不替代授权或幂等。

### 6.2 数据进入模型上下文前就必须完成最小化和鉴权

无权正文、完整手机号或过度工具返回一旦进入模型上下文，事后从最终答案删除也撤销不了暴露。RAG 鉴权、来源/版本/权限元数据、缓存绑定、字段白名单、日志最小化和删除传播是一条连续数据控制链。

### 6.3 安全结论的强度由证据链决定，而不是由输出或分数决定

模型拒答、一次正常输出、有效引用、高风险分、截图或文件数量都不单独证明系统安全或漏洞成立。可关闭的发现需要原始输入输出、环境版本、应用决定、工具/检索记录、可重复复测、残余风险和审批；旧失败证据必须保留。

## 8. 阶段 3 Web 基础计划

阶段 3 首先补强 Web 请求链和服务端边界，而不是直接测试真实目标。步骤 7–9 将形成独立准备报告；当前入口计划如下：

1. 学习 HTTP 请求/响应、方法、状态码、头部和正文，能把模型调用、RAG 查询和工具调用还原为可审计请求链。
2. 区分 Cookie/Session、认证和授权，重点练习对象级权限，解释“已登录但读取他人对象”为何仍是越权。
3. 学习输入验证、输出编码与 Markdown/HTML 渲染边界，为模型输出展示和 Prompt/工具参数处理建立确定性检查点。
4. 学习 URL 校验、SSRF 与网络出口边界，为未来 URL/浏览工具定义 allowlist、DNS/IP 检查和停止条件。
5. 学习命令/代码执行边界、RCE 基础和进程权限，为 Agent 执行器的最小权限、参数化接口和禁用任意 Shell 建立基础。
6. 学习 API 错误处理、幂等、超时、重试和审计关联，直接补强作品 3 的重复副作用与证据链缺口。
7. 所有实践仅使用本地靶场或明确授权平台、虚构账号和数据，并提前定义日志、重置、网络边界和停止条件。

本阶段 AI 应用安全的核心不是让模型更听话，而是把模型放进一条可验证、可限制、可追责的系统控制链。Prompt、检索文档、模型输出和工具返回都可能携带错误或恶意内容，因此身份与授权必须来自服务端，RAG 正文必须在进入上下文前完成权限过滤和最小化，工具动作必须经过 Schema、主体、动作、对象、参数、确认与幂等校验，最终输出还要经过引用、隐私和展示审查。平台隔离、日志关联和复测证据负责证明这些控制确实执行，而不是只看一次回答是否正常。下一阶段学习 HTTP、会话、对象权限、输出编码、URL 边界和错误处理，可以把目前抽象的 RAG 与 Agent 控制落实到真实请求路径，明确每个参数从哪里进入、在哪个服务端边界被校验、失败时留下什么证据。
