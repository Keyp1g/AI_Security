## 3. Agent 比聊天机器人更难的原因

1. **会规划多步动作**：早期的小错误可能在后续步骤累积，不再只是单轮错误文本。
2. **持久状态放大影响**：记忆污染、过期计划和跨会话数据可能影响未来行为。
3. **工具结果也是不可信输入**：返回可含用户内容、污染文本或错误信息，并进入下一轮推理。
4. **可能产生外部副作用**：读取、创建、发送、支付等动作可能真实改变系统状态。
5. **权限跨层**：模型、编排器、工具服务和业务对象都有边界，只在 Prompt 写规则无法覆盖。
6. **重试与并发会重复执行**：超时不等于失败，盲目重试可能重复创建或扣费。
7. **审计必须串起整条链**：仅保存最终回答无法解释哪个候选调用被谁、按哪版策略允许。

## 4. 模型责任与服务端责任

| 层 | 可以承担 | 不能作为安全保证 |
|---|---|---|
| 模型/规划器 | 理解请求、提出候选工具、生成结构化参数、解释结果 | 身份证明、授权、确认、高影响执行、日志真实性 |
| 编排/网关 | 工具白名单、Schema、调用预算、返回隔离、状态机 | 不能把模型自报字段直接变成授权事实 |
| 工具服务端 | 主体/对象/动作授权、参数上限、幂等、事务、最小返回 | 不能假设调用来自“内部 Agent”就可信 |
| 人工/可信 UI | 查看精确对象与影响、作高风险确认 | 不能用模糊的预先同意替代逐项确认 |

## 6. 最值得复盘的五个观察

- AGENT-010-03：数值字符串并未被自动转换，说明安全边界应避免宽松强制类型转换。
- AGENT-010-06：file_id 格式合法仍被对象授权拒绝，说明 Schema 不能替代权限。
- AGENT-010-08/09：同一业务参数只因可信确认状态不同而到达不同分支。
- AGENT-010-09/15：幂等键使重放返回相同模拟 ID，而非创建第二条记录。
- AGENT-010-18：检测到控制样式文本不是最核心结论；核心是工具返回永远不能直接授权下一动作。

## 7. 当前限制

- 工具、会话、文档和工单均在单一 PowerShell 进程中模拟。
- `confirmed` 是测试布尔值，不是生产级确认 token；未验证 actor、对象摘要、过期和撤销。
- 单线程串行用例不能证明并发幂等、事务或 TOCTOU 安全。
- JSONL 是可复核证据但不是防篡改审计系统。
- 未调用真实模型，不存在可评价的 Prompt/Response，也不能声称模型抵抗工具注入。
- 学习者尚未通过口头解释或闭卷回答证明概念掌握；文件存在与掌握不是同一验收项。
