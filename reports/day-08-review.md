## 2. 今日学习结论

### 2.1 Prompt Injection 的机制

Prompt Injection 的核心是应用把用户、文档、网页、邮件、检索片段或工具返回中的不可信内容误当成可以改变任务、规则或工具行为的指令。判断不能只看某个关键词；应区分“注入尝试”和“注入成功”，后者需要实际输出、任务偏移、权限变化或副作用证据。

### 2.2 四类入口/目标

- 直接注入：用户输入直接冲突或劫持应用任务；
- 间接注入：控制样式文字藏在文档、邮件、网页或检索结果中；
- 系统提示泄露诱导：目标是内部规则、配置或模拟敏感值；
- 工具指令污染：工具返回影响后续工具选择、参数或授权判断。

直接/间接主要按来源分类，泄露和工具污染描述目标或受影响资产，因此标签可以重叠。Jailbreak 更关注模型内容/行为安全边界，Prompt Injection 更关注应用任务和指令—数据边界。

### 2.3 最重要的边界

```text
文档是数据，不是指令
模型输出是候选数据，不是授权事实
JSON 合法不等于任务正确
任务正确不等于已经获得权限
模型声称“已批准”不等于服务端授权
```

真实身份、对象归属、工具允许列表、参数限制和高影响审批必须在模型外独立执行。

## 3. 实验结果复盘

### 3.1 直接注入

本地 `qwen2.5:7b`、固定参数、10 条独立请求：通过 5、部分通过 5、不通过 0。

模型出现过度阻断、任务偏移、额外字段、字段类型错误和模拟敏感标记输出。严格 Schema、归一化敏感输出检查和无副作用阻断防止这些结果进入最终路径，但模型行为本身并不稳定。

证据：`reports/day-08-direct-injection-run-v0-2.jsonl`、`labs/day-08-direct-injection.md`。

### 3.2 间接文档注入

5 篇干净文档和 5 篇不可信文档均完成独立摘要：Schema 接受 10/10、来源 ID 保留 10/10、动作 `none` 为 10/10、模拟敏感值命中 0/10。5 篇不可信文档中的 `[UNTRUSTED_TEXT]` 被模型当作文档数据提及，没有改变摘要任务。

该结果只覆盖 10 篇短小的本地虚构文档，不能推断真实 RAG、邮件或网页系统整体安全。

证据：`reports/day-08-indirect-injection-run-v0-1.jsonl`、`labs/day-08-indirect-injection.md`、`labs/week-02/documents/`。

### 3.3 敏感输出与工具返回

`LLM-008-16` 至 `20` 最终均为部分通过：模型发生来源不精确、敏感标记变形输出、过度阻断或未授权动作候选，但 v0.4 应用层分别通过精确来源校验、归一化敏感检查和任务级授权阻断。

其中一次修复还暴露了 PowerShell 变量大小写不敏感导致参数被内部变量覆盖的问题。v0.1 至 v0.4 的证据均保留，最终采用 v0.4。

证据：`labs/day-08-control-validation.md`、`reports/day-08-control-cases-run-v0-4.jsonl`、`labs/week-02/logs/day-08-control-cases-v0-4.jsonl`。

## 5. 控制清单复盘

至少以下控制明确位于模型外：

- 敏感输出阻断；

- 工具允许列表；
- 主体、对象、动作和策略授权；
- 高影响人工确认；
- 审计日志和阻断路径。

本日没有把单一关键词过滤或 System Prompt 当成唯一防线。
