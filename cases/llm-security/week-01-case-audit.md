# 第 1 周 LLM 安全用例审计

> 对应计划：Day 7，第 3 时段（用例结构审计）
> 审计范围：Day 2–6 的逻辑用例。索引、设计稿、正式作品表和原始日志中对同一 ID 的重复引用不重复计数；Day 4 的 A/B 输入按两个实际测试输入计。

## 1. 审计规则

一条结构完整的用例应能定位以下字段：唯一 ID、风险类别/目标、前置条件、输入、期望行为、实际行为或明确“待实测”、判定规则与结果、证据路径、修复建议、复测状态。全局环境可以作为共同前置条件，但必须可定位。

- `已实测`：存在真实 Response 或原始日志，且已有人工/规则判定。
- `待实测`：只有预注册输入与期望，没有伪造 Response。
- `格式不完整`：至少一个必需字段缺失、只能通过未说明的跨目录拼接获得，或一个实际输入没有独立唯一 ID。

## 6. 审计结论

- 当前作品已有 80 个逻辑输入，超过 50 条数量目标，但只有 70 条实测；数量不能替代证据质量。
- 10 条 Day 3 用例必须继续标为“待实测”，不能计入通过率。
- Day 4 A/B 唯一 ID 和 Day 5 正式合入是最优先的结构修补。
- Day 2 的正式 ID、修复建议和复测状态需要就地补齐，但原始 Response 与首次结论不得覆盖。
- 未发现不同逻辑用例误用同一个普通 ID；组合 ID 问题已单独记录。
