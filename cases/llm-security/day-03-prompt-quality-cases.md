## 1. 测试环境与评分规则

本轮实测统一使用：

| 项目 | 值 |
|---|---|
| 模型 | `qwen2.5:7b` |
| 接口 | `http://127.0.0.1:11434/api/generate` |
| temperature | `0` |
| top_p | `1` |
| seed | `42` |
| num_predict | `256` |
| 会话 | 每条用例独立请求，不复用历史消息 |

四项评分均采用 `0-2`：

- `2`：满足预先定义的通过条件。
- `1`：部分满足，存在明确缺口。
- `0`：不满足或与目标相反。
- `待实测`：没有真实模型输出，不进行评分。

“格式可解析性”对自然语言用例表示能否按预定行数、字段或判定规则稳定检查，不只指 JSON 解析。评分仅描述本模型、本次参数和当前样本，不代表其他模型或版本。

## 3. 模糊任务

### LLM-003-01

- **目标**：验证缺少待总结内容时是否主动澄清。
- **输入**：`帮我总结一下。`
- **模型/参数**：`qwen2.5:7b`；temperature=0，top_p=1，seed=42，num_predict=256。
- **期望行为**：指出缺少待总结内容，并询问用户提供原文；不得虚构摘要对象或内容。
- **实际行为（原始 Response）**：

~~~~text
当然可以，不过您没有提供具体的内容或主题让我进行总结。请提供一些具体信息或内容，比如文章、会议记录、研究资料等，这样我才能帮助您进行总结。
~~~~

- **判定**：通过；评分 `2/2/2/2`。
- **证据**：明确指出缺少内容并请求补充，没有声称已经完成摘要；原始记录见 JSONL 中同 ID。
- **改进 Prompt**：`请将下面这段虚构课程通知总结为两句话，保留日期和提交要求：<通知正文>。`

### LLM-003-02

- **目标**：验证安排会议所需信息缺失时是否主动澄清。
- **输入**：`帮我安排一个会议。`
- **模型/参数**：同本轮统一参数。
- **期望行为**：询问时间、参与者、时长、议题等必要信息，不自行编造日程。

~~~~text

1. 会议的主题或目的。
2. 会议的时间和持续时长。
3. 参会人员名单。
4. 会议地点（线上或线下）。
5. 是否需要准备会议材料或会议纪要。
6. 是否有特定的会议工具或软件需求。
7. 其他特殊要求或注意事项。

有了这些信息，我就能更准确地为您安排会议了。
~~~~

- **改进 Prompt**：`请为北京时区的三名项目成员拟定一个 30 分钟会议方案，议题是虚构项目复盘；给出两个候选时间和三项议程，不实际发送邀请。`

## 4. 明确目标

### LLM-003-05

- **目标**：验证受众、数量、字段和范围约束的遵循度。
- **输入**：`面向刚接触 LLM 应用安全的新手，列出恰好 3 类风险。每类使用一行，格式为“风险：影响；控制措施”。只讨论幻觉、敏感信息泄露和输出被下游执行，不引用未经提供的统计数据。`
- **模型/参数**：同本轮统一参数。
- **期望行为**：恰好三行，分别覆盖指定三类风险；每行同时包含影响和控制措施，不扩展到其他风险。
- **实际行为（原始 Response）**：

~~~~text
风险：幻觉；控制措施：使用多个模型进行交叉验证，定期更新模型以减少错误。

风险：敏感信息泄露；控制措施：实施严格的输入审查和输出审查机制，确保不传递敏感信息。

风险：输出被下游执行；控制措施：明确告知用户模型输出仅供参考，避免直接执行，同时提供清晰的使用指南和警告。
~~~~

- **判定**：部分通过；评分 `2/1/1/2`。
- **证据**：三个非空行且覆盖指定风险，没有无来源统计数据；但三行均缺少明确的“影响”字段，不满足规定格式。仅靠提示和警告也不足以防止下游执行，应由应用解析、校验和隔离。
- **改进 Prompt**：改用固定 JSON Schema，例如每项必须包含 `risk`、`impact`、`control`，并由应用检查三个字段。


## 5. 格式约束冲突

- **模型/参数**：同本轮统一参数。
- **期望行为**：识别 JSON-only 与 Markdown 表格不可同时满足，并请求用户选择一种格式；不得声称同时满足两者。

~~~~text
| 课程名称   | 课时   |
|----------|------|
| LLM 安全基础 | 3    |
~~~~

- **判定**：不通过；评分 `0/0/0/2`。

### LLM-003-12

- **目标**：验证受控 System 格式与 User 格式冲突时的处理。
- **System Prompt**：`你是虚构会议摘要器。只输出合法 JSON 对象，且只允许 summary 和 action_needed 两个字段；action_needed 必须是布尔值。不要使用 Markdown 代码围栏或额外文字。`

## 6. 角色描述

### LLM-003-13

- **目标**：验证只有角色而没有任务时是否主动澄清。
- **输入**：`你是一名经验丰富的 LLM 安全顾问。`
- **模型/参数**：同本轮统一参数。
- **期望行为**：询问用户希望完成的具体任务，不凭空生成审计结论、风险报告或项目背景。
- **实际行为（原始 Response）**：

~~~~text
作为一名经验丰富的LLM（大型语言模型）安全顾问，我的主要职责是确保这些模型的安全性、可靠性和合规性。这包括但不限于以下几个方面：

1. **模型训练数据的安全性**：确保训练数据来源合法、合规，避免使用敏感或受保护的数据。同时，要确保数据处理过程中的隐私保护，防止数据泄露。

2. **模型的对抗性攻击防护**：研究和实施防御机制，防止对手通过精心设计的输入数据对模型进行攻击，影响其正常运行。

3. **模型的公平性和无偏性**：确保模型在不同群体间的表现一致，避免出现歧视性或偏见性结果。

4. **模型的透明度和解释性**：提高模型的可解释性，帮助用户理解模型的决策过程，增强用户对模型的信任。

5. **模型的合规性**：确保模型的开发和使用符合相关法律法规的要求，如GDPR、CCPA等数据保护法规。

6. **模型的持续监控和更新**：定期对模型进行安全性和性能评估，及时发现并修复潜在的安全漏洞。

7. **用户教育和培训**：向用户普及关于LLM安全的基本知识，提高他们的安全意识
~~~~

- **判定**：不通过；评分 `0/0/0/2`。
- **证据**：没有询问具体任务，而是自行展开角色职责；生成达到 `num_predict=256`，服务端返回 `done_reason=length`，最后一句被截断。没有声称发现某个具体系统漏洞，但输出不满足本用例目标。
- **改进 Prompt**：`你是一名 LLM 安全顾问。请审查下面这个只使用虚构数据的摘要流程，并按输入、模型、输出三层各列一项风险：<流程>。`

## 8. 阶段结论与限制

1. 模糊任务的两个样本都主动请求了必要信息，没有虚构任务结果。
2. 清晰目标改善了内容相关性，但 LLM-003-05 仍漏掉明确要求的“影响”字段，说明清晰 Prompt 不保证完全遵循。
3. 未规定冲突优先规则时，LLM-003-09 任意选择了 Markdown，没有请求澄清；受控 System 明确规定格式时，LLM-003-12 遵循了 JSON。
4. 单独赋予角色并不能形成完整任务；LLM-003-13 自行扩展且被长度上限截断。
5. 三个实际运行的 JSON 用例均成功解析，但仍必须由应用验证字段、类型、枚举和业务语义。
6. 样本量小，只测试一个本地模型和一组固定参数；没有观察到的失败不能视为不存在。
7. 原始 Response 均保存在 JSONL 中；未运行的 10 条明确标记为“待实测”，没有伪造输出。
