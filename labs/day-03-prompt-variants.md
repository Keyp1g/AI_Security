# 第 3 天：背景、目标与约束单变量实验

> 阶段：Day 3
> 模型：`qwen2.5:7b`
> 接口：`http://127.0.0.1:11434/api/generate`
> 参数：`temperature=0`、`top_p=1`、`seed=42`、`num_predict=256`
> 原始证据：`reports/day-03-prompt-variants-run.jsonl`
> 用例定义：`labs/day03-prompt-variants.json`

## 1. 实验设计

所有内容均为虚构课程场景。每组运行两个版本，仅修改表中列出的变量：

| 组别 | 唯一变化 | 固定项 | 观察项 |
|---|---|---|---|
| 背景 | 未提供背景 / 加入三条相关事实 | 模型、任务、输出要求、参数 | 是否使用给定事实，是否在缺少事实时停止猜测 |
| 目标 | 宽泛目标 / 可验收目标 | 模型、三条背景、一段话格式、参数 | 是否明确覆盖当前进展、下一步、负责人、截止日期 |
| 约束 | 无额外约束 / 加入 JSON、字段、日期和禁项 | 模型、任务、三条背景、参数 | 输出长度、结构、解析性及无来源扩展 |

这里的“一组运行两次”指该组的两个变量水平各运行一次。固定 seed 用于减少无关随机差异，不能消除模型版本或服务端实现带来的变化。

## 2. 背景变量

### VAR-BG-0：未提供背景

完整 Prompt：

~~~~text
任务：为项目经理总结当前进展，并指出下一步负责人和截止日期。
背景：未提供。
输出要求：只输出一个合法 JSON 对象，字段必须且只能为 summary 和 next_step；信息不足时使用字符串 missing_input，不要猜测。
~~~~

原始 Response：

~~~~text
```json
{
  "summary": "missing_input",
  "next_step": "missing_input"
}
```
~~~~

观察：模型没有虚构进展、负责人或日期，正确表达信息不足；但在 JSON 外增加了 Markdown 代码围栏，因此整个原始 Response 不能直接作为 JSON 解析。

### VAR-BG-1：加入三条相关背景

完整 Prompt：

~~~~text
任务：为项目经理总结当前进展，并指出下一步负责人和截止日期。
背景：1. 课程目录已经完成；2. 王宁需要在 2026-09-20 前完成复核；3. 材料仅用于内部试讲，受众是刚接触 LLM 安全的新同事。
输出要求：只输出一个合法 JSON 对象，字段必须且只能为 summary 和 next_step；信息不足时使用字符串 missing_input，不要猜测。
~~~~

原始 Response：

~~~~text
```json
{
  "summary": "课程目录已经完成，材料仅用于内部试讲，受众是刚接触 LLM 安全的新同事。",
  "next_step": {
    "responsible_person": "王宁",
    "due_date": "2026-09-20"
  }
}
```
~~~~

观察：输出正确引用三条背景，并在下一步中保留王宁和日期；没有观察到新增业务事实。它仍添加了代码围栏。“字段只能为 summary 和 next_step”没有明确限制嵌套字段和字段类型，因此不能把 `next_step` 对象判为违反已写规则，但这暴露了 Schema 不完整。

### 背景组结论

本次两个样本显示，相关背景使模型能够从 `missing_input` 转为生成有事实依据的摘要。该结果不能证明“背景越多越好”：背景应必要、相关、来源可追踪，并避免敏感数据和无关噪声。

## 3. 目标变量

### VAR-GOAL-0：宽泛目标

完整 Prompt：

~~~~text
目标：处理以下信息。
背景：1. 课程目录已经完成；2. 王宁需要在 2026-09-20 前完成复核；3. 材料仅用于内部试讲，受众是刚接触 LLM 安全的新同事。
输出格式：使用一段话。
~~~~

原始 Response：

~~~~text
为了确保课程内容的准确性和时效性，王宁需在2026年9月20日前完成对已完成课程目录的复核工作。此次复核仅用于内部试讲，面向刚接触LLM安全的新同事，因此内容需确保既全面又易于理解。
~~~~

观察：虽然目标仅写“处理”，模型仍自行选择了总结方式并覆盖进展、负责人、日期和受众；同时加入“时效性”“全面”等输入未明确提供的评价或要求。

### VAR-GOAL-1：可验收目标

完整 Prompt：

~~~~text
目标：为项目经理总结当前进展，并在下一步中明确写出负责人和截止日期。
背景：1. 课程目录已经完成；2. 王宁需要在 2026-09-20 前完成复核；3. 材料仅用于内部试讲，受众是刚接触 LLM 安全的新同事。
输出格式：使用一段话。
~~~~

原始 Response：

~~~~text
当前项目进展顺利，课程目录已经完成，下一步是请王宁在2026年9月20日前完成复核工作，确保内容准确无误。此材料仅用于内部试讲，面向刚接触LLM安全的新同事。
~~~~

观察：输出直接使用“当前进展”和“下一步”组织内容，并明确负责人及日期；但“进展顺利”和“确保内容准确无误”仍属于没有直接来源的推断或目的性补充。

### 目标组结论

两个样本都覆盖四个事实，因此不能声称精确目标在所有维度上必然更好。本次可观察差异是：精确目标让输出结构更贴近验收语言，宽泛目标则由模型自行猜测处理方式。两者都出现轻微无来源扩展，说明明确目标不能替代事实边界。

## 4. 约束变量

### VAR-CONSTRAINT-0：无额外输出约束

完整 Prompt：

~~~~text
目标：为项目经理总结当前进展，并指出下一步负责人和截止日期。
背景：1. 课程目录已经完成；2. 王宁需要在 2026-09-20 前完成复核；3. 材料仅用于内部试讲，受众是刚接触 LLM 安全的新同事。
~~~~

原始 Response：

~~~~text
### 项目进展总结

1. **课程目录完成**：课程目录已经全部完成，这标志着课程框架已经搭建完毕，为后续内容的填充奠定了基础。
2. **复核任务**：王宁负责的复核工作将在2026年9月20日前完成。这是确保课程内容准确性和质量的重要步骤。
3. **内部试讲受众**：课程材料仅用于内部试讲，受众为刚接触LLM（大型语言模型）安全的新同事。这意味着内容需要简洁明了，易于理解。

### 下一步行动计划

1. **负责人**：王宁
2. **任务**：完成课程内容的复核工作
3. **截止日期**：2026年9月20日

请王宁在截止日期前完成复核工作，确保课程内容的准确性和质量。如果有任何问题或需要进一步讨论的地方，请随时与我联系。
~~~~

观察：输出可读且包含四个关键信息，但较长，并增加了“全部完成”“框架已经搭建”“后续内容填充”“保证质量”和联系邀请等没有直接来源的内容。

### VAR-CONSTRAINT-1：加入格式、字段和禁项

完整 Prompt：

~~~~text
目标：为项目经理总结当前进展，并指出下一步负责人和截止日期。
背景：1. 课程目录已经完成；2. 王宁需要在 2026-09-20 前完成复核；3. 材料仅用于内部试讲，受众是刚接触 LLM 安全的新同事。
约束：只输出一个合法 JSON 对象，字段必须且只能为 summary 和 next_step；next_step 必须同时包含负责人和 YYYY-MM-DD 日期；不得使用 Markdown 代码围栏，不得添加背景中没有的事实。
~~~~

原始 Response：

~~~~text
{
  "summary": "课程目录已完成，材料仅用于内部试讲，受众是刚接触 LLM 安全的新同事。",
  "next_step": {
    "负责人": "王宁",
    "截止日期": "2026-09-20"
  }
}
~~~~

观察：原始 Response 可直接解析为 JSON，只包含两个顶层字段，负责人和日期均存在，没有代码围栏；未观察到无来源事实。

### 约束组结论

本次加入明确约束后，输出从 325 个字符降至 119 个字符，并变为可直接解析的 JSON，且减少了无来源扩展。这只说明本模型、本次参数和该样本中的可观察改善，不代表所有任务都应使用同一种格式，也不证明约束能替代应用校验。

## 5. 限制

- 每个变量水平只运行一次，样本量不足以估计输出分布。
- 只测试一个本地模型和一组固定参数。
- 固定 seed 不保证跨模型版本、硬件或服务端实现完全复现。
- 背景组的 Prompt 没有禁止代码围栏，也没有定义嵌套字段类型，暴露了测试设计本身的缺口。
- 目标组两个版本都覆盖了关键事实，结论只能基于具体措辞和无来源扩展，不能夸大为普遍规律。
- 本实验没有连接真实业务、外部工具或敏感数据，也没有验证业务授权。
