# 学习单元 12：合成敏感信息样例集

> 用途：验证敏感信息检测、脱敏、角色展示、工具响应裁剪、日志最小化和删除传播。
> 数据边界：本文全部内容均为人工构造的无效占位数据，不对应真实个人、机构、账户或凭据，不得替换为历史日志、聊天记录或代码仓库中的真实信息。

## 1. 使用规则

1. 每条样例只设定一个主要测试位置，避免一次测试混合多个泄露面。
2. 受控合成数据文件可保存原始占位值；普通日志、无权角色响应和公开报告只保存替换值、类型、哈希或 sample_id。
3. 测试记录应引用 sample_id，不重复复制原始值到无关文件。
4. 模拟 API Key 具有明显无效前缀，只用于检测形态，不进行认证或联网验证。
5. 手机号为专用合成模式，不用于拨号、短信或个人识别。
6. 测试结束后按每条记录的销毁说明清理 Prompt、工具响应、缓存、日志和临时输出中的副本。

## 9. 学习者理解抽查与边界修正

### 模拟 Key 与手机号采用不同替换方式

学习者正确认识到处理方式应根据数据类型、使用目的和风险分级决定。模拟 Key 在响应和普通日志中没有保留局部字符的业务必要，因此默认完整替换为规则标签；手机号在已授权业务场景中，可以保留有限的前后位用于人工核对，同时遮盖中间部分。

需要避免把理由表述为“任何密钥片段都必然可用于签名、撞库或破解”。片段是否具有实际利用价值取决于凭据格式、熵、验证机制和攻击条件。完整遮盖的核心依据是最小披露：下游只需要知道命中了哪种规则和哪个 sample_id，不需要看到秘密的任何部分。若运维确有识别同一凭据的需求，应优先保存不可逆指纹、专用 secret ID 或受控证据引用，而不是任意截取原文。

### RAG 样例的删除传播

学习者正确指出，原始手机号进入检索链后，可能形成文档片段、向量、元数据、检索结果和语义缓存等派生数据，因此删除请求必须沿数据血缘传播。验证应分别检查原始文档是否删除、向量或片段是否仍可召回、检索缓存是否仍命中，以及新的模型上下文是否还包含该值。

KV 缓存是否包含可识别内容、是否跨请求共享、是否落盘以及能否按单条记录删除，取决于模型服务的具体实现。没有架构或配置证据时，应把它列为待确认的数据位置，而不是默认存在持久化且可独立检索的 KV 副本。

### 普通日志只记录 sample_id 和规则 ID

好处是普通日志不再形成新的敏感原文副本，同时仍可统计规则命中、触发告警、关联请求并追踪删除传播。限制是普通日志本身不足以复现原始输入、核对遮盖结果或调查误报和漏报。

需要复核原文时，应通过访问受控且有保留期限的证据区保存必要样本或完整输入输出，并在普通日志中只保存证据引用、不可逆哈希、规则版本和处理结果。这样可以把日常可观测性与敏感证据访问分开。
