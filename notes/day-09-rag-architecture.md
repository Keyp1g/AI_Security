# Day 9：RAG 基础架构与安全边界

## 1. 学习结论

RAG（Retrieval-Augmented Generation，检索增强生成）不会在提问时重新训练模型，也不会修改模型参数。它先从外部知识库检索与问题相关的内容，再把检索结果临时加入本次模型上下文。

RAG 中必须分开判断三件事：

```text
相似度：文档和问题像不像
owner_scope：当前用户能不能看
trust_level：该来源能不能支撑当前用途
```

检索排名高只能说明相关，不能证明内容真实、来源可信或用户有权访问。权限过滤必须由模型外的确定性服务端逻辑执行，并在无权正文进入模型上下文之前完成。

## 2. 教材、架构推论与实验观察

### 2.1 教材明确陈述

- RAG 在收到问题后，从知识库检索相关知识以增强模型输入。
- Top-K 语义相似文本可以作为模型生成答案时的上下文。
- 少量污染文本可能改变特定问题的检索与生成结果。
- 间接 Prompt Injection 可以隐藏在模型可能检索或摄入的外部内容中。
- RAG 应用需要关注检索质量、覆盖范围、数据隐私和安全问题。

### 2.2 根据架构得到的合理推论

- 文档切分后仍须保留来源、版本、权限和信任元数据。
- 权限过滤不能交给生成模型，也不能等到生成之后再做。
- 文档删除需要同步处理 chunk、Embedding、索引、副本和缓存。
- 引用存在不等于答案正确，还要验证引用内容是否真正支持回答。
- 哈希只能证明文件与某一版本一致，不能证明内容事实正确。

### 2.3 本日实际观察

- 5 组污染对照中，4 组召回了不可信文档。
- 2 组的 Top1 候选发生改变，3 组的模型输出发生改变。
- 越权场景在模型调用前被阻断，无权正文没有进入最终上下文。
- 一次没有观察到输出变化，不能证明其他查询、模型或 RAG 系统安全。

## 3. 八个核心组件

| 组件 | 输入 | 输出 | 主要控制方 | 主要安全风险 |
|---|---|---|---|---|
| 文档 | PDF、网页、Markdown、工单等原始资料 | 待处理的原始内容及来源信息 | 数据所有者、接入服务 | 伪造来源、未授权资料、过期或恶意内容进入系统 |
| 切分 | 原始文档及其元数据 | 带 `document_id`、版本、权限和信任标签的 chunk | 文档处理管道 | 切分后丢失来源或权限，无法引用、撤销或隔离 |
| Embedding | 查询或文档片段文本 | 表示语义特征的数值向量 | Embedding 服务 | 相似度被误当成真实性；模型或版本变化造成索引不一致 |
| 向量库/索引 | 向量、chunk、来源、版本及安全元数据 | 可搜索的索引记录 | 索引服务、数据管理员 | 元数据污染、跨租户混存、删除后残留、索引版本失配 |
| 检索 | 查询向量、用户允许范围、索引 | 带分数和元数据的候选片段 | 检索服务和服务端授权策略 | 越权召回、不可信内容高排名、无关内容进入候选 |
| 重排 | 初步候选、查询及来源特征 | 重新排序后的候选 | 重排器、应用策略 | 只优化相关性而忽略权限和信任；攻击内容操纵排名 |
| 生成 | 用户问题、最终授权上下文、应用规则 | 答案草稿和引用声明 | LLM 编排层 | 间接注入、幻觉、错误归因、泄露上下文、伪造引用 |
| 引用与输出审查 | 答案草稿、引用、最终候选及策略 | 接受、弃答、阻断或人工复核决定 | 确定性应用层、必要时人工 | 引用越界、引用与结论不符、低信任内容被直接发布 |

Embedding 与本日原型中的字符二元组 Jaccard 不同。后者只是可验证的离线检索模拟，不等同于生产 Embedding 或向量数据库。

## 4. 数据流

本日采用 13 个节点：

```text
① 文档接入
  → ② 来源/权限/信任标记
  → ③ 内容检查
  → ④ 切分
  → ⑤ 向量化
  → ⑥ 写入索引
  → ⑦ 查询鉴权
  → ⑧ 权限过滤与检索
  → ⑨ 重排
  → ⑩ 上下文组装
  → ⑪ 模型生成
  → ⑫ 引用校验与输出审查
  → ⑬ 返回结果并记录日志
```

| 节点 | 主要风险 | 关键控制 | 可复核证据 |
|---|---|---|---|
| ① 文档接入 | 未批准文档入库 | 批准目录、数据源白名单 | 文件名、接入决定、文档 ID |
| ② 元数据标记 | 来源、权限或信任标签被伪造 | 服务端生成或验证元数据 | source、owner_scope、trust_level |
| ③ 内容检查 | 恶意控制样式、敏感数据或格式异常 | 内容检查、人工升级、失败关闭 | 检查结果、原因码 |
| ④ 切分 | chunk 与原文档失去关联 | 强制继承 ID、版本和权限 | chunk ID、document_id、version |
| ⑤ 向量化 | 模型版本不一致、语义碰撞 | 固定模型版本、记录配置 | Embedding 版本、参数 |
| ⑥ 写入索引 | 污染、重复、陈旧版本残留 | 哈希、索引版本、撤销流程 | SHA-256、索引批次 |
| ⑦ 查询鉴权 | 客户端伪造身份或角色 | 服务端身份验证和策略查询 | identity、策略版本、allowed_scopes |
| ⑧ 检索 | 跨范围召回或低信任内容高排名 | 权限预过滤、阈值、Top-K | 鉴权前后候选及分数 |
| ⑨ 重排 | 相关性覆盖信任要求 | 信任感知策略、来源交叉验证 | 重排前后顺序及原因 |
| ⑩ 上下文组装 | 无权或不可信文本进入 Prompt | 最小上下文、数据边界、最终候选白名单 | final_context_document_ids、完整 Prompt |
| ⑪ 模型生成 | 幻觉、间接注入、错误引用 | 固定任务规则、结构化输出、无工具副作用 | 模型、参数、原始 Response |
| ⑫ 输出审查 | 伪造引用、答案与证据不一致 | 引用白名单、忠实度检查、人工复核 | citation_status、application_decision |
| ⑬ 返回与日志 | 敏感正文被重复写入日志、污染结果扩散 | 日志最小化、分级访问、回滚追踪 | ID、版本、判定、撤销记录 |

## 5. 四个主要信任边界

| 信任边界 | 风险 | 至少一个模型外控制点 |
|---|---|---|
| 外部文档 → 受控语料库 | 投毒、伪造来源、错误权限 | 准入列表、来源登记、哈希和版本 |
| 用户身份 → 检索范围 | 客户端伪造角色、跨范围读取 | 服务端鉴权并生成 `allowed_scopes` |
| 检索结果 → 模型上下文 | 间接注入、低信任内容影响回答 | 权限过滤、明确 DOCUMENT 数据边界、最小上下文 |
| 模型输出 → 用户或工具 | 幻觉、泄露、伪造引用、未授权动作 | Schema、引用白名单、输出审查和人工复核 |

Prompt 中声明“文档是不可信数据”只能降低模型误执行的概率，不能形成强制安全隔离。检索片段一旦进入上下文，模型已经能够读取它，因此无权文档必须在此之前被阻断。

## 6. 权限、信任和相关性的边界

### 6.1 权限过滤

权限判断是确定性的：

```text
owner_scope ∈ allowed_scopes
```

不满足条件的片段不得进入模型上下文。可以在检索前过滤或在检索时加入过滤条件；生产系统应尽量提前过滤，避免无权内容进入候选日志、缓存或下游处理。

### 6.2 来源信任

`trust_level` 描述来源或处理链的信任程度，不直接证明内容真实。可信资料也可能过期或记录错误；低信任资料也可能恰好说对。信任标签用于决定是否降权、交叉验证、阻断或人工复核，不能代替权限判断。

### 6.3 检索相关性

相似度只回答“文本与问题是否接近”。它不能证明：

- 内容真实；
- 来源权威；
- 用户有权访问；
- 文档不含控制样式文本；
- 文档适合支撑当前用途。

## 7. 检索污染的边界

检索污染不修改模型参数。它让错误、过期、低信任或恶意内容进入知识库，并在相关查询下进入模型上下文。训练数据中毒通过训练过程影响模型参数，可能普遍降低能力，也可能只在特定触发条件下激活。

检索污染也不一定包含间接 Prompt Injection：虚假事实被召回并影响回答已经属于检索污染；只有外部文本中的指令被模型当成指令执行时，才同时构成间接 Prompt Injection。

污染内容被发现后，不能只删除原文件。还要处理：

```text
原始文档 → chunk → Embedding → 索引/副本 → 检索缓存 → 生成缓存 → 历史回答与引用
```

完成撤销后，应使用曾经命中污染内容的查询进行回归测试。

## 8. 输出端引用与审查

引用检查至少包括两层：

1. 引用有效性：引用 ID 是否属于本次最终授权候选，版本是否一致；
2. 引用忠实度：引用内容是否真正支持答案中的结论。

对于 `insufficient_evidence`，空引用可以是合理的安全弃答。对于声称已经回答的结果，缺少引用、引用越界或引用不能支持结论时，应阻断或复核。

模型输出只是候选结果。最终应用决定可以是：

- `accepted`；
- `insufficient_evidence`；
- `denied_scope`；
- `blocked_by_citation_validation`；
- `needs_review_untrusted_context`。

## 10. 当前限制与验收结论

- 每篇短文只有一个 chunk，没有验证长文档、重叠切分和截断。
- 使用字符二元组 Jaccard 模拟检索，没有验证生产 Embedding、向量数据库或真实重排器。
- 用户、权限和数据集均为本地虚构值，没有连接真实身份系统或业务知识库。
- 只测试单一模型、固定参数和小样本，结论不能外推到全部 RAG 系统。
- 自动检查了引用是否属于最终候选，但引用内容是否支持结论仍主要依赖固定用例和人工判断。

经过主动回忆，已经能够解释 RAG 与微调的区别、相关性与可信度的边界、模型前权限过滤、检索污染与训练数据中毒的区别，以及文档撤销为何需要覆盖索引和缓存。Day 9 理论目标与实验目标均已形成可复核证据。
