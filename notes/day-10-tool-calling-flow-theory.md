# Day 10：Tool Calling 控制链理论

> 公开范围：已完成的 Tool Calling 控制链、阻断点、幂等与审计理论
> 状态：本部分已通过主动回忆与综合场景；三个模拟工具契约理论留待下一阶段

## 学习目标

理解模型提出的候选工具调用如何经过模型外的确定性控制后到达执行器，并能指出每个阻断点解决的问题、所需证据及其不可替代的边界。

## 完整控制链

```text
用户请求
→ 意图与会话预检
→ 模型选择候选工具
→ 生成候选参数
→ 工具 allowlist 与严格 Schema
→ 服务端工具、动作、对象和参数授权
→ 风险确认与幂等检查
→ 受控执行
→ 工具结果隔离
→ 输出审查
→ 审计与展示
```

链路分成三个性质不同的阶段：模型负责理解目标和提出候选动作；确定性服务端负责安全决定；受控执行器负责产生读取或状态变化。模型输出格式正确或语气确定，都不会使候选动作自动取得权限。

## 五个阻断点

### 1. 身份与任务范围

主体身份从可信服务端会话取得。用户输入、记忆或模型输出中的“我是管理员”“已经批准”只是文本声明。入口预检只能做初步范围判断，真正执行前仍需根据最新对象、参数和资源状态重新授权。

### 2. 工具 allowlist

应用级 allowlist 决定某个工具是否被注册为可用能力。Prompt 中“只使用这三个工具”是行为提示，可能受误解、上下文截断或注入影响；代码中的 allowlist 才是强制边界。

需要进一步区分：

- 应用级 allowlist：应用是否提供这个工具；
- 角色工具权限：当前主体是否可以使用这个工具；
- 参数级权限：已获工具权限的主体能否使用这组参数。

例如 `visitor` 使用 `create_mock_ticket` 会在角色工具权限处拒绝；`analyst` 已有工具权限，但请求 `severity=high` 时会在参数级权限处拒绝。

### 3. 严格 Schema

Schema 验证候选参数的必需字段、类型、长度、枚举、格式和额外字段。它只证明结构符合契约：

```text
Schema 通过
≠ 身份有效
≠ 工具或对象有权
≠ 参数组合符合业务权限
≠ 副作用已经确认
```

### 4. 服务端授权

授权应按以下维度重新计算：

```text
主体 × 工具 × 动作 × 对象 × 参数条件
```

角色来自服务端会话，资源归属和业务状态来自权威数据源。入口处的预检不能代替执行前授权，否则可能遗漏对象归属变化、参数篡改、二次注入或检查与执行之间的状态变化。

### 5. 确认、幂等与执行出口

确认回答“当前主体是否批准针对这组精确参数产生副作用”。可信确认应绑定主体、工具、对象、参数摘要、有效期和一次性标识；模型生成的 `confirmed=true` 只是候选字段。

幂等回答“同一个逻辑请求是否已经成功执行”。例如：

```text
REQ-007 首次成功 → MOCK-1007
REQ-007 再次提交 → 返回 MOCK-1007，不重复创建
```

确认防止未经批准的副作用，幂等防止重试和消息重复造成二次副作用。确认后的调用仍可能被重复提交；幂等命中也不能证明用户曾经批准，因此两者不能互相替代。

## 工具结果隔离

工具返回进入了新的信任边界：

```text
工具结果
→ 返回 Schema 校验
→ 标记 untrusted_tool_result
→ 过滤允许字段
→ 检测异常或控制样式文字
→ 输出审查或下一轮候选规划
```

返回正文中的“请立即调用另一个工具”属于不可信数据，不会自动成为系统指令。若业务确实需要新的调用，它必须重新经过 allowlist、Schema、工具/对象/参数授权、确认和幂等检查。

## 审计与受控证据

普通审计日志应保存足以还原决定的最小字段：

```text
call_id、session_ref、actor_id、server_role
tool、argument_keys、arguments_hash
schema_version、policy_version、decision_code、block_stage
confirmation_ref、request_id、幂等首次/重放状态
副作用类别、结果 ID、信任标签、异常类型、证据引用
```

普通日志不默认保存完整 query、summary、文件正文或工具返回原文。确有取证需要的原文进入访问受控的证据区，并设置加密、最小权限、保留期和访问审计；普通日志通过证据 ID 和哈希关联原文。

## 综合场景验收

场景条件：可信会话为 `analyst`；调用 `create_mock_ticket`；参数为 low/triage；可信确认与主体和参数绑定；`REQ-007` 已成功关联 `MOCK-1007`；返回正文提出调用 `admin_cleanup`。

学习者得出并解释了以下结论：

1. 应用 allowlist、Schema、角色工具权限、参数权限和可信确认均通过。
2. 幂等检查命中已有 `REQ-007`，返回 `MOCK-1007`，本次新增副作用为零。
3. `admin_cleanup` 只是工具结果中的不可信内容，不触发自动调用。
4. 普通日志保存调用与决定元数据，必要原文进入受控证据区。
