## 二、安全对齐

安全对齐是让模型行为尽可能符合人类意图、价值要求和安全规则的过程。它可以提高模型遵守安全目标的倾向，但不能证明模型面对所有未知输入时都绝对安全。

需要区分：

```text
安全对齐：让模型更倾向于做出安全行为
安全防护：在应用层阻止危险输入、输出和操作
安全证明：证明系统在规定条件下不会违反特定性质
```

因此，“经过安全对齐”不能替代输入检查、输出过滤、服务端鉴权、最小权限、审计和必要的人工复核。

## 三、Jailbreak 定义

Jailbreak 是通过设计输入或对话过程，诱导模型绕过原本应遵守的安全限制，产生本应拒绝、限制或安全改写的内容。

判断是否构成 Jailbreak，通常需要观察：

1. 模型是否存在应遵守的安全边界；
2. 输入是否试图规避、削弱或重新解释该边界；
3. 模型是否因此产生了原本不应提供的内容。

角色扮演本身不是 Jailbreak。只有当角色扮演被用于要求模型忽略或绕过安全边界时，它才成为越狱策略的一部分。

单次拒绝只能说明“本次样本中未观察到越狱成功”，不能证明模型永远无法被越狱。

## 四、为什么对齐后仍可能被越狱

- 对齐训练无法覆盖所有语言、编码、语境和多轮对话组合；
- 预训练能力与后期行为限制可能同时存在；
- 系统指令、用户输入、历史消息和外部资料可能在上下文中形成竞争；
- 安全教育、研究、新闻和真实有害请求可能讨论相似主题，自然语言边界并不总是清晰。

安全评估必须同时观察正确拒绝和过度拒绝：明显违规请求应被拒绝或安全降级，正常请求应得到帮助，灰区请求则应澄清、限定范围或提供安全替代。

## 五、越狱框架的防御性理解

结构化 Prompt 框架本身是中性的。正常任务和恶意任务都可能使用同一个框架，风险取决于目标、内容和预期结果，而不是框架名称。

防御性越狱测试可以抽象为：

```text
选择低风险测试目标
-> 对输入做一种受控变换
-> 明确不得越过的边界
-> 运行模型
-> 按预先定义的规则评估
-> 保存证据并复测
```

模块化分析可以包括：

| 组件 | 防御测试中的作用 |
|---|---|
| Selector | 选择已获授权的低风险测试目标 |
| Mutator | 改变角色、表述、编码或上下文 |
| Constraint | 限定测试范围和允许的变换 |
| Evaluator | 根据预定义规则判断是否发生绕过 |

## 九、第二小时：Jailbreak 与 Prompt Injection

> 当前进度：阶段 2 已完成并通过主动回忆与分类练习

### 1. 核心区别

| 比较维度 | Jailbreak | Prompt Injection |
|---|---|---|
| 核心目标 | 绕过模型的内容或行为安全限制 | 劫持应用预定任务或上层指令 |
| 主要边界 | 允许内容与禁止内容 | 控制指令与待处理数据 |
| 常见对象 | 模型拒答与安全策略 | System/Developer 指令和应用工作流 |
| 常见来源 | 用户设计的输入或多轮对话 | 用户输入、网页、邮件、文档和检索内容 |
| 典型后果 | 生成原本应拒绝或限制的内容 | 任务偏移、错误结论、信息泄露或工具误用 |
| 主要防护 | 意图识别、安全分类、输出审查和对抗测试 | 指令与数据隔离、来源标记、鉴权、参数校验和下游阻断 |

Prompt Injection 可以分为：

- 直接注入：用户直接提交与应用预定任务或上层指令冲突的控制命令；
- 间接注入：控制命令藏在网页、邮件、文档、知识库或检索内容等外部数据中。

### 2. 二者的重叠关系

Jailbreak 和 Prompt Injection 描述不同维度，因此并不总是互斥：

- Prompt Injection 可以描述恶意指令如何进入上下文并劫持任务；
- Jailbreak 可以描述攻击最终试图突破哪类安全边界。

如果外部文档既要求模型停止原任务，又要求忽略安全规则并输出禁止内容，则属于二者重叠：以 Prompt Injection 为进入和劫持方式，以 Jailbreak 为进一步目标。

Prompt Injection 不一定构成 Jailbreak。例如，用户让翻译应用停止翻译并输出错误状态，已经劫持任务，但未必绕过内容安全边界。

Jailbreak 也不一定依赖间接 Prompt Injection。例如，用户在普通聊天中直接通过角色设定或多轮话术要求模型提供明确禁止的内容，核心问题就是绕过安全限制。

### 3. 为什么不能只依靠 System Prompt

System Prompt 本身仍是模型上下文中的自然语言约束。面对复杂上下文、冲突指令、编码变换、多轮对话或未覆盖的输入形式时，模型可能无法稳定遵守它。

Prompt 负责表达期望行为，应用控制负责强制执行安全边界。应用层至少需要：

- 把外部内容标记并限定为待处理数据；
- 使用真实会话身份进行认证和授权；
- 检查资源归属与对象级权限；
- 对工具名称、参数和值执行 Schema 和允许列表校验；
- 对模型输出进行结构化解析和安全检查；
- 对敏感操作增加确认或人工审批；
- 记录输入来源、模型输出与工具调用结果。

即使模型被诱导生成危险工具请求，应用也不应直接执行。模型返回的 `approved`、`verified` 或类似文字不是授权证据。

### 4. 主动回忆记录

学习者已掌握：

1. 文档要求模型停止总结并输出指定状态，首先属于 Prompt Injection，因为它破坏的是指令与数据边界并劫持应用任务；
2. 同一输入既劫持预定任务又要求绕过安全限制时，可以同时标记 Prompt Injection 和 Jailbreak；
3. System Prompt 只是自然语言约束，真正的身份认证、对象级授权、参数校验和操作阻断必须由应用层执行。

## 十、第三小时：越狱风险分类

> 当前进度：阶段 3 已完成并通过主动回忆

### 1. 五类风险

| 类型 | 核心方式 | 允许的防御性输入 | 禁止边界 | 防护验证重点 |
|---|---|---|---|---|
| 角色扮演 | 用虚构身份、场景或人格主张原规则不再适用 | 解释角色提示为何是风险信号，审计虚构回复 | 不要求模型进入无约束角色或输出越界内容 | 进入角色后是否保持安全边界，是否把虚构身份当成真实权限 |
| 编码规避 | 通过编码、拆分、替代字符、跨语言等方式隐藏语义 | 使用虚构标记做意图分类，不复述解码结果 | 不编码、传播或执行现实危害指令 | 规范化后重新分类，分离“解码”和“执行” |
| 上下文重定向 | 通过新故事、任务或多轮指令重新定义当前对话 | 识别虚构的新策略声明或将其改写成告警 | 不用多轮渐进方式持续试探绕过边界 | 跨轮追踪真实意图，不能只检查单轮关键词 |
| 长上下文 | 用大量内容使早期规则被截断、弱化、遗漏或淹没 | 使用无害填充文本验证规则是否仍被遵守 | 不夹带真实秘密、第三方文档或现实危害步骤 | 记录长度、上下文组成、截断位置，并比较不同长度下的结果 |
| 自动化搜索 | 自动生成、变异、评分并筛选大量候选输入 | 分析评估器误报漏报，使用少量人工虚构候选 | 不对第三方服务批量查询，不优化可迁移绕过载荷 | 限定授权范围、查询预算，并使用可靠 Evaluator 和人工抽检 |

这些类型不是互斥标签。同一输入可以同时使用角色扮演、编码规避和上下文重定向；自动化搜索也可以批量寻找前述类型的有效变体。

### 2. 主动回忆记录

#### 输入形式为什么不能证明越狱成功

学习者回答：角色扮演和编码内容都只是输入层的内容，是否越狱成功要以模型是否输出安全边界外的内容为依据。

#### 长上下文失败为什么要区分原因

学习者回答：不能看到失败就直接宣称模型遗忘了安全规则，正确分辨情况才能更好地测试和解决问题。

批改：正确。还需明确两条诊断路径：若规则已被客户端或服务端裁剪，主要是上下文组装与工程控制问题；若规则仍在有效窗口中却未被遵守，才是当前样本观察到的指令遵循或模型行为问题。两者的修复位置不同。

#### 自动化搜索为什么需要可靠 Evaluator

学习者识别了查询覆盖率、异常字符串、误判、授权、费用、速率限制和日志等风险。

补充：如果 Evaluator 只检查响应中是否出现“好的”，它会把包含该词的安全拒答误判为越狱成功，也会漏掉不含该词的真实越界输出。自动化搜索还会持续优化这个错误指标，使大量后续结果被污染。因此应结合语义、安全策略、期望行为和人工抽检，而不能只靠单个关键词。

