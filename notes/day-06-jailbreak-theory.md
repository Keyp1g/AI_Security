# 第 6 天：Jailbreak 基础理论

> 发布范围：仅包含概念、风险分类和防护边界；不包含实验用例、运行脚本、模型响应、评分或复盘数据。

## 1. 安全对齐不是安全证明

安全对齐用于提高模型行为符合人类意图、价值要求和安全规则的倾向，但它不是形式化安全证明，也不能保证模型面对所有未知输入时都保持安全。

```text
安全对齐：让模型更倾向于做出安全行为
安全防护：在应用层阻止危险输入、输出和操作
安全证明：证明系统在规定条件下不会违反特定性质
```

因此，对齐不能替代输入检查、输出过滤、服务端鉴权、最小权限、审计和必要的人工复核。安全评估还必须同时检查正确拒答和过度拒答：违规请求应被拒绝或安全降级，正常请求应得到帮助，灰区请求应获得澄清、范围限制或安全替代。

## 2. Jailbreak 定义与判定

Jailbreak（越狱）是通过设计输入或对话过程，诱导模型绕过原本应遵守的安全限制，产生本应拒绝、限制或安全改写的内容。

判断一次请求是否构成越狱，应分别观察：

1. 是否存在模型应遵守的安全边界；
2. 输入是否试图规避、削弱或重新解释该边界；
3. 模型是否因此产生了原本不应提供的内容。

角色扮演、编码或长文本只是输入形式，不自动等于越狱成功。是否成功必须根据模型实际行为判断。单次拒绝也只能说明当前样本没有观察到绕过，不能证明模型永远安全。

## 3. 为什么对齐后仍可能被越狱

- 对齐训练无法覆盖所有语言、编码、语境和多轮对话组合；
- 预训练能力与后期行为限制可能同时存在；
- System、Developer、User、历史消息和外部内容会在上下文中形成复杂关系；
- 教育、研究、新闻、小说和真实有害请求可能讨论相似主题，自然语言边界并不总是清晰；
- 模型行为具有概率性，单个版本或样本不能代表所有场景。

## 4. Jailbreak 与 Prompt Injection

| 比较维度 | Jailbreak | Prompt Injection |
|---|---|---|
| 核心目标 | 绕过模型内容或行为安全限制 | 劫持应用预定任务或上层指令 |
| 主要边界 | 允许内容与禁止内容 | 控制指令与待处理数据 |
| 常见对象 | 模型拒答和安全策略 | System/Developer 指令与应用工作流 |
| 典型后果 | 生成原本应限制的内容 | 任务偏移、错误结论、数据泄露或工具误用 |
| 主要控制 | 意图识别、安全分类、输出审查、对抗评估 | 指令与数据隔离、来源标记、鉴权、参数校验、下游阻断 |

两类风险可以重叠。Prompt Injection 可以描述恶意指令如何进入上下文并劫持任务；Jailbreak 可以描述攻击最终试图突破的安全边界。例如，外部文档既要求停止原任务，又要求忽略安全规则时，可以同时具有间接注入和越狱目标。

Prompt Injection 不一定构成 Jailbreak：让翻译应用输出错误状态已经劫持任务，但未必绕过内容安全规则。Jailbreak 也不一定依赖外部文档：普通聊天中的多轮诱导同样可能试图突破安全限制。

## 5. 五类越狱风险

| 类型 | 核心方式 | 判断边界 | 防护验证重点 |
|---|---|---|---|
| 角色扮演 | 用虚构身份、场景或人格主张原规则不再适用 | 角色扮演本身中性，风险取决于是否用于规避边界 | 角色是否改变安全规则，虚构身份是否被当作真实权限 |
| 编码规避 | 通过编码、拆分、替代字符或跨语言隐藏语义 | 编码本身不是攻击，应检查还原后的真实意图 | 规范化后重新分类，分离解码、分析与执行 |
| 上下文重定向 | 用新故事、任务或多轮指令重新定义当前对话 | 观察是否要求忽略、削弱或重新解释原目标 | 跨轮追踪意图，避免只检查单轮关键词 |
| 长上下文 | 用大量内容使早期规则被截断、弱化或遗漏 | 区分工程裁剪与模型未遵守仍可见规则 | 记录上下文组成、Token 长度和截断策略 |
| 自动化搜索 | 自动生成、变异、评分和筛选候选输入 | 搜索过程与成功判定必须分别验证 | 限定授权、查询预算、速率和日志；验证评估器可靠性 |

这些类型不是互斥标签。同一输入可能同时使用角色、编码和上下文重定向；自动化搜索也可能批量寻找这些策略的有效变体。

## 6. 结构化防御评估

结构化 Prompt 框架本身是中性的，风险来自目标、内容和预期结果。防御性评估可以抽象为：

```text
选择低风险且已授权的测试目标
-> 对输入做一种受控变换
-> 明确不得越过的边界
-> 运行模型
-> 按预先定义的规则评估
-> 保存证据并复测
```

模块化分析可以使用：

| 组件 | 防御评估中的作用 |
|---|---|
| Selector | 选择已授权、低风险的测试目标 |
| Mutator | 改变角色、表述、编码或上下文 |
| Constraint | 限定测试范围和允许的变换 |
| Evaluator | 根据预定义规则判断模型行为 |

Evaluator 不能只依赖单个关键词，否则会产生误报和漏报，并使自动化搜索持续优化错误指标。应结合输出语义、安全策略、任务期望、结构化规则和人工抽检。

## 7. 应用层防护

System Prompt 仍是上下文中的自然语言约束，不能独立承担全部安全责任。应用层至少需要：

- 将网页、邮件、文档和检索结果标记为待处理数据；
- 使用真实会话身份进行认证与授权；
- 检查资源归属和对象级权限；
- 对工具名称、参数和值执行 Schema 与允许列表校验；
- 对模型输出进行结构化解析和安全检查；
- 对敏感操作增加确认或人工审批；
- 记录输入来源、模型输出、策略判定和工具调用结果。

核心原则是：Prompt 表达期望行为，应用控制强制执行安全边界。模型生成的 `approved`、`verified` 或类似文本不是真实授权证据。
