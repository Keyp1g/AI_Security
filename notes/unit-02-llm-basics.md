## LLM 输入到输出流程

```text
Prompt
  -> Tokenize
  -> 加载上下文与指令
  -> 模型推理：计算下一个 Token 的概率分布
  -> 解码策略：选择下一个 Token
  -> 重复生成，直到停止条件
  -> Decode
  -> Response
```

| 步骤 | 输入 | 输出 | 需要观察的安全问题 | 可记录证据 |
|---|---|---|---|---|
| Prompt | 用户文本、附件或结构化字段 | 原始请求内容 | Prompt 注入、越权要求、敏感信息进入请求 | 完整原始 Prompt、来源、时间 |
| Tokenize | 原始文本及编码 | Token 序列 | Token 数超限、截断、不可见字符或编码差异绕过过滤 | 分词器/版本、Token 数、截断提示 |
| 加载上下文与指令 | Token 序列、系统/开发者指令、历史消息、检索内容 | 排序后的模型上下文 | 指令层级冲突、间接注入、早期证据被截断或弱化 | 上下文组成、顺序、长度、检索文档标识 |
| 模型推理 | 当前上下文和已训练参数 | 下一个 Token 的概率分布 | 幻觉、偏见、敏感内容生成、概率性不稳定 | 模型名称/版本、完整请求响应、日志 |
| 解码策略 | 概率分布、temperature、top_p 等 | 被选中的下一个 Token | 随机性、重复、格式不稳定、不同参数导致结果变化 | temperature、top_p、seed（若支持） |
| 重复生成 | 已生成 Token 和停止条件 | 完整 Token 序列 | 输出过长、停止条件失效、敏感内容逐步生成 | max_tokens、stop 条件、生成长度 |
| Decode | Token 序列 | 人类可读文本或结构化数据 | 编码还原差异、特殊字符、JSON/HTML 下游注入 | 原始 Token（若可得）、解码文本 |
| Response | 解码后的模型输出 | 返回给用户或交给下游系统的结果 | 输出未过滤就执行、渲染注入、敏感信息泄露 | 原始响应、过滤结果、下游执行/解析记录 |

### 必答问题

1. **Prompt 是否等于模型内部知识？**

   不是。Prompt 是本次请求提供的输入和条件；模型内部知识以训练后参数中的统计表示存在，Prompt 只能影响当前推理，不能保证调用到真实、完整或最新的事实。

2. **为什么同一 Prompt 可能得到不同 Response？**

   推理得到的是概率分布，temperature、top_p、随机种子和服务端实现可能使每一步选择不同。即使参数固定，模型版本、隐藏上下文、工具结果或服务端更新也可能造成差异，因此应记录完整参数和运行环境。

3. **在哪些位置加入输入校验、输出过滤和人工审批？**

   输入校验应放在 Prompt 进入模型前，检查长度、编码、敏感信息和明显的越权内容；输出过滤应放在 Decode/Response 之后，检查格式、敏感内容和危险指令。涉及真实权限变更、外部发送或高影响决策时，还应在下游执行前加入人工审批和最小权限控制。

### 安全观察要点

- 输入侧：确认原始 Prompt、Token 长度和上下文来源可追溯。
- 模型侧：把输出视为概率性生成，记录模型版本和解码参数，并对事实、权限和安全策略做独立验证。
- 输出侧：任何自动执行、渲染、发送或写入操作前，都要进行结构化解析、策略检查和必要的人工审批。
