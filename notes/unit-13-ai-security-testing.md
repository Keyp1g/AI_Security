# 学习单元 13：AI 安全测试方法论

> 当前范围：步骤 1——阅读并拆解 AI 红队流程  
> 目标：把教材中的概括性流程扩展为可授权、可交接、可停止、可复核的 11 阶段测试闭环。  
> 证据边界：本笔记整理教材、学习计划与学习单元 8–12 的既有本地证据，不表示已经对新的模型、网站、工具或业务系统执行测试。

## 1. 学习结论

AI 红队不是大量尝试攻击 Prompt，而是围绕明确授权、风险假设、受控执行和证据闭环开展的系统化评估。单纯增加 Prompt 数量只能扩大执行样本，不能自动补足范围、责任、判定、修复和复测。

完整流程必须回答五个问题：

```text
输入：凭什么开始当前阶段？
产出：交给下一阶段什么？
责任人：谁对产出负责，谁协作和复核？
质量门槛：哪些可观察条件满足后才允许继续？
失败时动作：应返工、阻断、停止上报，还是降低结论强度？
```

流程主线如下：

```text
项目方案 -> 授权与范围 -> 团队与职责 -> 威胁建模 -> 测试设计
-> 受控执行 -> 证据保存 -> 风险评分 -> 修复建议 -> 复测 -> 结构化报告
```

这不是一次性的直线流程：授权与停止条件贯穿全程；新发现可以使流程返回威胁建模或测试设计；修复与复测构成循环；结构化报告只是当前证据状态的快照，不是永久安全证明。

## 2. 教材内容、计划扩展与结论边界

### 2.1 教材明确强调的内容

教材将 AI 红队流程概括为项目方案、组建多元团队、设计多层测试、迭代执行和结构化报告，并强调：

- AI 红队同时关注传统应用安全、模型特有风险以及公平性、隐私和有害内容等责任 AI 风险；
- 测试应覆盖基础模型/API 层和完整应用/UI 层，不能只观察聊天输出；
- AI 输出具有概率性，模型、Prompt 或安全措施改变后需要重新测试；
- 自动化适合生成变体、批量执行、记录和初筛，复杂语境与影响判断仍需人工参与；
- 测试结果应形成结构化证据，驱动修复和再次测试；
- 红队测试用于揭示和增进风险认知，不能替代系统化度量与风险缓解；
- 个别失败案例不能直接表示某类危害的普遍发生率。

### 2.2 本学习单元的流程扩展

学习计划把教材的五个概括阶段扩展为 11 个阶段，主要补出了以下容易被省略的控制：

- 将“授权与范围”从项目方案中独立出来，作为执行前的强制门禁；
- 在测试设计前增加威胁建模，使每个用例能够回到资产、角色和信任边界；
- 将证据保存、风险评分、修复建议和复测分别建模，防止发现、判断与处置混为一谈；
- 为每个阶段规定输入、产出、责任人、质量门槛和失败时动作；
- 明确授权撤销、异常发现和超范围请求的停止规则。

### 2.3 解释边界

- 教材作者说明相关内容包含项目经验、厂商分享和交流所得，应作为经验性框架，而不是唯一行业标准。
- “传统系统是确定性的、AI 系统是概率性的”是教学上的概括。传统分布式系统也可能因并发、状态、网络和时序出现不稳定；AI 系统则额外受到采样、模型版本和上下文变化影响。
- 单次模型失败可以证明该条件下观察到了失败样本，不能证明所有模型或所有请求都会失败。
- 单次通过、模型拒答、应用阻断和工具未执行分别描述不同事实，均不能单独证明整个系统安全。
- 文档中写有控制不表示控制已经部署；模拟器通过不表示真实集成通过；待实测不等于通过。

## 3. 五类角色与职责边界

每个阶段使用“主责、协作、复核”三个角度分配职责。主责人对产出完整性负责，协作者提供必要信息或实施控制，复核人独立判断质量门槛是否满足。

| 角色 | 主要职责 | 不应替代的职责 | 典型证据 |
|---|---|---|---|
| 产品负责人 | 定义业务目标、关键功能、目标用户、影响场景、非目标和处置优先级；协调授权与资源 | 不凭业务直觉替代技术证据，也不单方面改写测试判定 | 项目方案、资产优先级、范围批准、风险接受记录 |
| 测试人员 | 建模风险、设计用例、受控执行、保存原始证据、记录观察事实和复测结果 | 不自行扩大范围，不把模型生成内容当授权，不修改原始响应以符合预期 | 用例、执行记录、Prompt/Response、日志 ID、复测记录 |
| 应用/平台负责人 | 提供架构、版本、配置和控制点；维护隔离环境；实施确定性控制、修复和回滚 | 不独自确认自己实施的修复已经有效，不以“模型已拒答”代替服务端控制 | 架构图、配置版本、策略决定、修复提交、部署与回滚记录 |
| 数据负责人 | 确认数据类别、使用目的、访问范围、脱敏、保留、删除和证据区规则 | 不因数据是测试数据就忽略来源、最小化和保留要求 | 数据清单、分类标签、访问决定、保留策略、删除记录 |
| 复核人 | 独立核对范围、证据、判定、评分、限制和过度结论；处理自动判定与人工判断差异 | 不凭印象覆盖原始事实，不删除不利结果，不把证据不足写成通过 | 复核意见、人工判定、差异理由、报告批准记录 |

责任分配遵循以下原则：

1. 测试执行人与最终复核人尽量分离。
2. 修复实施者可以提供证据，但修复有效性应由测试人员复测并由复核人确认。
3. 数据负责人决定数据处理边界，应用/平台负责人负责技术执行，两者不能互相替代。
4. 产品负责人可以接受残余业务风险，但不能把未执行或证据不足的测试改写成技术通过。

## 4. 11 阶段 AI 红队流程

### 4.1 项目方案

- **目标**：说明为什么测试、测试什么业务能力以及预期形成什么决策。
- **输入**：产品与功能描述、目标用户、架构概览、已知限制、已有安全措施、业务风险关注点和资源约束。
- **产出**：测试目标、测试对象、非目标、关键资产、初始风险优先级、成功标准、交付物和资源需求草案。
- **主责人**：产品负责人。
- **协作与复核**：测试人员、应用/平台负责人、数据负责人；复核人检查目标是否可验证。
- **质量门槛**：测试对象、业务目标、关键资产、预期交付物和非目标均有明确记录；目标可以转化为后续可观察的测试问题。
- **失败时动作**：信息缺失时退回补充；目标不可验证时重写；不得跳过项目方案直接生成攻击用例。

### 4.2 授权与范围

- **目标**：确定测试是否被允许，以及允许在何时、对哪些资产、以哪些动作执行。
- **输入**：项目方案、资产与所有者清单、环境说明、数据分类、访问方式、风险容忍度和联系人信息。
- **产出**：授权记录，至少包含允许时间、允许资产、模拟角色、允许动作、禁止动作、数据处理方式、紧急联系人、停止条件、授权有效期和撤销方式。
- **主责人**：产品负责人或资产授权人。
- **协作与复核**：应用/平台负责人确认技术资产，数据负责人确认数据边界，测试人员确认动作可执行，复核人检查是否存在歧义。
- **质量门槛**：所有关键字段均存在；允许与禁止动作没有重叠；资产、身份、数据和副作用边界可核对；紧急联系人可用。
- **失败时动作**：缺少任何关键授权字段时状态为“未授权/不执行”；授权过期、撤销或范围发生实质变化时立即停止，不允许测试人员自行补充或推断权限。

### 4.3 团队与职责

- **目标**：确保每项风险、资产、测试动作、数据处置和最终判定都有明确责任归属。
- **输入**：授权范围、目标风险域、系统组件、所需业务/技术/数据知识和独立复核要求。
- **产出**：角色与职责表、主责/协作/复核关系、联系方式、升级路径、值守安排以及利益冲突说明。
- **主责人**：测试负责人。
- **协作与复核**：产品、应用/平台、数据负责人共同确认职责；复核人确认自己具有独立检查条件。
- **质量门槛**：五类角色均有明确承担者；高影响测试有现场监控与停止联系人；执行、修复和复核没有不可接受的职责冲突。
- **失败时动作**：关键职责无人承担时阻断后续设计；缺少必要领域专家时缩小范围或记录未覆盖项，不以临时猜测代替专业判断。

### 4.4 威胁建模

- **目标**：把宽泛的安全关注点转化为资产、角色、信任边界和可检验的风险假设。
- **输入**：架构图、数据流、角色权限、资产清单、授权范围、已有控制、学习单元 8–12 的历史用例和证据。
- **产出**：资产与角色清单、信任边界、攻击面、威胁路径、风险假设、受影响组件、已有控制、优先级和明确排除项。
- **主责人**：测试人员。
- **协作与复核**：应用/平台负责人确认数据流和控制点，数据负责人确认数据资产，产品负责人确认业务影响，复核人检查假设与证据是否分开。
- **质量门槛**：模型、Prompt/编排、RAG、工具、输出、日志和数据边界按实际系统选择性覆盖；每个高优先级假设能回到具体资产、角色和信任边界。
- **失败时动作**：架构或数据流不清时返回项目方案或范围阶段；发现未知资产时先确认所有者和授权；没有证据的内容只能记录为假设。

### 4.5 测试设计

- **目标**：把威胁假设转化为另一位测试者能够复现且不会越过授权边界的最小用例。
- **输入**：威胁模型、授权范围、控制清单、环境版本、判定规则、数据与副作用限制。
- **产出**：用例 ID、目标、前置条件、完整无害输入、执行步骤、控制变量、期望行为、判定规则、证据字段、重复策略、停止条件和清理/回滚方案。
- **主责人**：测试人员。
- **协作与复核**：应用/平台负责人检查环境和回滚，数据负责人检查样例数据，复核人检查判定是否可观察。
- **质量门槛**：每个用例关联一个风险假设；输入和期望可核对；未使用真实秘密；没有禁止动作；模型版本、Prompt、上下文、参数和重复次数有预注册要求。
- **失败时动作**：判定含糊时返工；需要超范围资产或真实数据时阻断并走范围变更；不能安全控制副作用的用例标为未授权/不执行或改用模拟器。

### 4.6 受控执行

- **目标**：在授权、隔离、监控和停止规则有效的条件下执行预注册用例。
- **输入**：已批准用例、当前有效授权、环境基线、模型/Prompt/索引/工具版本、合成数据、日志与回滚准备。
- **产出**：逐次原始请求与响应、模型和参数、上下文来源、应用判定、工具候选与授权结果、副作用状态、异常记录和执行摘要。
- **主责人**：测试人员。
- **协作与复核**：应用/平台负责人监控环境和出口，数据负责人处理异常数据事件，产品负责人或紧急联系人决定重大范围问题，复核人抽查执行一致性。
- **质量门槛**：执行前重新确认授权和版本；每次动作都能关联用例 ID；重复次数符合设计；模型失败、应用阻断、工具失败和环境失败分别记录；未产生未计划的真实副作用。
- **失败时动作**：版本或前置条件不符时阻断该用例；工具或环境故障单独记录，不写成模型结论；出现授权撤销、真实秘密、外部连接或不可控副作用时立即停止并按停止规则处理。

### 4.7 证据保存

- **目标**：保存足以复核观察事实、执行条件和判定过程的证据，同时控制敏感数据和保留范围。
- **输入**：原始 Prompt/Response、应用与工具日志、环境和策略版本、执行参数、人工观察、截图或日志 ID、异常处置记录。
- **产出**：原始证据包、证据索引、来源与哈希、访问级别、保留期限、分析记录以及原始判定与人工复核差异。
- **主责人**：测试人员。
- **协作与复核**：数据负责人规定存储与保留；应用/平台负责人提供可信日志；复核人检查证据是否支持结论。
- **质量门槛**：模型/版本/入口/参数、完整 Prompt、完整 Response、上下文来源、执行结果、耗时、HumanModified、判定规则、限制和证据路径可定位；原始记录与分析结论分开保存。
- **失败时动作**：不得重造或补写缺失的模型输出；证据不完整时标为“证据待补”“待实测”或“需复核”；误收真实敏感数据时停止扩散、限制访问并通知数据负责人。

### 4.8 风险评分

- **目标**：在证据基础上比较处置优先级，而不是用总分替代专业判断。
- **输入**：已确认或待复核的发现、影响资产、可复现证据、暴露范围、利用条件、评分规则版本和不确定性。
- **产出**：严重性、可复现性、影响范围、利用复杂度等维度分数，评分理由、证据引用、人工复核状态和不确定性说明。
- **主责人**：复核人。
- **协作与复核**：测试人员解释复现证据，产品负责人解释业务影响，应用/平台和数据负责人确认技术与数据范围。
- **质量门槛**：每个分数都能回溯实际证据；观察事实与潜在影响分开；待实测项不与已确认发现合并；涉及权限、敏感数据或副作用的项目经过人工复核。
- **失败时动作**：证据不足时使用暂定或待复核状态，不强行评分；评分分歧保留双方理由；不得通过平均分掩盖高影响低频风险。

### 4.9 修复建议

- **目标**：把发现转化为责任组件明确、可实施、可验证和可回滚的处置方案。
- **输入**：发现与证据、根因分析、现有控制、资产影响、业务约束、评分和残余风险。
- **产出**：修复措施、责任人、优先级、验收条件、临时缓解、回滚方案、关联用例和复测范围。
- **主责人**：应用/平台负责人；数据治理问题由数据负责人主责。
- **协作与复核**：测试人员提供复现条件，产品负责人确定业务优先级，复核人检查建议是否针对根因。
- **质量门槛**：建议落到具体组件和控制点；模型外强制控制没有被 Prompt 建议替代；验收条件可测试；高影响项有临时风险降低措施或明确接受记录。
- **失败时动作**：建议无法验证或只描述目标时退回细化；修复需要扩大数据或权限范围时重新评估；无法立即修复时记录临时控制、所有者、期限和残余风险。

### 4.10 复测

- **目标**：验证修复是否消除原问题，并检查相关功能和安全边界是否产生回归。
- **输入**：修复版本、原失败用例、相关回归用例、环境基线、授权、修复验收条件和旧证据。
- **产出**：修复前后对比、逐次复测证据、通过/失败/阻断/待实测判定、新发现、残余风险和版本关联。
- **主责人**：测试人员。
- **协作与复核**：应用/平台或数据负责人提供修复环境，复核人独立检查结果，产品负责人确认残余业务风险。
- **质量门槛**：原用例和必要回归用例均已执行；模型、Prompt、应用和工具版本明确；非确定性场景按规则重复；修复没有产生未计划副作用；结果可与旧证据比较。
- **失败时动作**：原问题仍出现则重新打开并返回修复阶段；出现新风险时建立新发现并关联根因；环境不可比时结论为无效或待复测，不能标为通过。

### 4.11 结构化报告

- **目标**：向决策者清晰呈现本次测试做了什么、观察到什么、证据支持什么以及仍不知道什么。
- **输入**：授权和范围、环境、方法、用例、证据索引、评分、修复、复测和限制。
- **产出**：包含文档控制、摘要、范围、架构与信任边界、方法、发现、证据、影响、根因、修复、复测、残余风险和未验证项的报告。
- **主责人**：测试负责人。
- **协作与复核**：复核人批准事实与结论，产品负责人确认业务表述，应用/平台和数据负责人确认修复与数据事实。
- **质量门槛**：每项发现可追溯到用例和证据；“观察事实、风险推断、限制”明确分开；待实测、阻断、未授权/不执行不写成通过；报告范围与授权一致。
- **失败时动作**：缺少证据链接时降低结论强度或退回补证；发现敏感原文时移入受控证据区并在报告中只保留引用；范围、评分或复测状态不一致时不得发布。

## 5. 阶段交接关系

| 上游交接 | 下游必须得到的内容 | 不能用什么替代 |
|---|---|---|
| 项目方案 -> 授权与范围 | 测试对象、业务目标、资产与非目标 | 口头的“可以测” |
| 授权与范围 -> 团队与职责 | 资产、动作、数据、时间、停止和联系人边界 | 测试人员的个人判断 |
| 团队与职责 -> 威胁建模 | 组件、资产和风险域的责任人 | 无所有者的架构猜测 |
| 威胁建模 -> 测试设计 | 可追踪的风险假设、资产与控制 | 随机收集的攻击 Prompt |
| 测试设计 -> 受控执行 | 可复现步骤、判定规则、停止和回滚方案 | 执行后再决定什么算成功 |
| 受控执行 -> 证据保存 | 未修改的输入输出与环境状态 | 人工回忆或美化后的摘要 |
| 证据保存 -> 风险评分 | 可复核事实、影响对象与不确定性 | 仅凭测试者印象评分 |
| 风险评分 -> 修复建议 | 风险理由、优先级和责任组件 | 只看总分排序 |
| 修复建议 -> 复测 | 修复版本、验收条件和关联用例 | 开发者声明“已经修好” |
| 复测 -> 结构化报告 | 修复前后证据、残余风险和未验证项 | 单次通过结果 |

## 6. AI 测试的额外记录要求

传统应用测试中的身份、资产、请求、日志和版本记录仍然需要保留。AI 系统还要增加以下字段：

| 记录项 | 最低内容 | 原因 |
|---|---|---|
| 模型身份 | 提供方、本地/远程入口、模型或部署 ID、版本/摘要、调用日期或证据批次 | 模型升级可能改变行为，模型名称相同也不一定表示部署相同 |
| 推理参数 | temperature、top_p、seed、最大输出、超时和其他影响采样的参数 | 区分随机波动、配置变化和真实修复效果 |
| Prompt 版本 | 系统/开发者模板版本、内容哈希、变量填充方式和完整测试输入 | Prompt 变化可能改变任务、边界和输出结构 |
| 上下文来源 | 历史消息、文档/片段 ID、工具结果 ID、来源、版本、信任标签和权限范围 | 判断内容从哪里进入模型，区分相关性、可信度和授权 |
| 非确定性处理 | 重复次数、独立会话要求、采样策略、停止条件和统计口径 | 单次结果不足以代表稳定性，重复也不能无限外推 |
| 工具调用与副作用 | 候选工具、参数摘要、Schema、服务端授权、确认、幂等、执行结果和新增副作用数 | 模型提出动作不等于动作被授权或执行 |
| 输出下游处理 | 解析器、Schema、引用检查、敏感信息检查、编码、渲染和最终展示决定 | 原始模型输出与用户最终看到或系统执行的内容可能不同 |
| 数据保留 | 普通日志字段、受控原始证据、访问级别、保留期限、删除和脱敏规则 | 测试证据本身可能含敏感或危险内容，需要最小化与隔离 |
| 人工修改与复核 | HumanModified、自动判定、人工判定、差异原因和复核人 | 防止把人工修正后的文本误写成模型原始行为 |

### 6.1 非确定性不等于不可测试

AI 输出具有概率性，因此需要固定已知变量、记录不可控变量并按预注册规则重复。重复测试的作用是描述本批样本的稳定性，不是把有限样本提升为普遍规律。

应分别记录：

```text
模型原始行为
应用层解析或阻断行为
工具服务端授权与执行行为
最终展示或副作用
```

例如，模型生成越权工具调用而服务端拒绝时，可以同时得到“模型产生危险候选”和“应用控制按本次规则阻断”两个事实，不能简单合并成“通过”或“系统安全”。

## 7. 全流程停止规则

停止规则优先于执行计划、用例数量和进度要求。触发后只能进行保护现场、最小必要处置和通知，不继续主动探测。

### 7.1 授权撤销、过期或实质变化

**触发条件：**

- 资产所有者或授权人撤销授权；
- 授权有效期结束；
- 测试环境、资产所有者、数据类别、允许动作或副作用范围发生实质变化；
- 紧急联系人要求暂停。

**动作：**

1. 立即停止新的请求、工具调用和自动化任务；
2. 保存停止前已经产生的最小必要证据，不为了补证继续操作；
3. 记录停止时间、原因、最后一个用例和可能存在的副作用；
4. 通知授权人、测试负责人和相关资产负责人；
5. 尚未执行的项目标记为“未授权/不执行”，不能计入通过率；
6. 只有取得新的书面授权并完成环境复核后才可恢复。

### 7.2 异常发现

**触发条件：**

- 发现真实凭据、真实个人数据或不在样例清单中的秘密；
- 出现意外网络连接、真实邮件/工单/支付/文件修改或其他外部副作用；
- 系统资源失控、循环调用、重复副作用或无法回滚；
- 日志、证据或隔离机制失效，可能继续扩大数据暴露；
- 当前现象可能属于真实安全事件而非预期测试结果。

**动作：**

1. 停止受影响用例；无法确认影响边界时停止整个批次；
2. 禁用或隔离相关连接器、凭据和执行出口，但不破坏现有证据；
3. 保存已有请求 ID、日志 ID、环境版本和副作用状态，避免继续打开或传播敏感原文；
4. 通知紧急联系人、应用/平台负责人和数据负责人；必要时进入事件响应流程；
5. 由复核人区分已观察事实、风险推断和未知影响；
6. 在根因受控、环境恢复且重新授权前不得恢复测试。

### 7.3 超范围请求

**触发条件：**

- 请求增加未授权资产、角色、接口、数据、时间或动作；
- 测试者、开发者或其他人员要求“顺便验证”计划外问题；
- 原用例需要访问真实服务、真实数据或产生禁止副作用才能继续。

**动作：**

1. 不执行该请求，并记录提出者、请求内容和所需范围；
2. 判断是否可用本地 fixture、合成数据或模拟工具回答原问题；
3. 确需扩大范围时返回项目方案、授权与范围及威胁建模阶段；
4. 获得新授权后重新设计用例，不能把新动作偷偷附加到旧用例；
5. 拒绝或未执行的请求不写成安全通过。

### 7.4 恢复测试的共同条件

停止后恢复至少需要：

- 新授权或授权仍有效的书面确认；
- 异常原因和影响边界已经形成记录；
- 外部连接、副作用、数据和资源控制恢复；
- 必要的回滚、清理和事件处置完成；
- 用例、停止条件和证据要求按新情况更新；
- 测试负责人和复核人共同确认可以恢复。

## 8. 质量门槛、停止条件和判定状态的区别

| 概念 | 回答的问题 | 未满足时的典型动作 | 示例 |
|---|---|---|---|
| 质量门槛 | 当前阶段的产出是否足以交给下一阶段？ | 返工或阻断交接 | 用例没有可观察判定规则，退回测试设计 |
| 停止条件 | 继续执行是否可能越权、扩大影响或失去控制？ | 立即暂停、保留现场、通知和重新授权 | 意外连接外部服务或出现真实秘密 |
| 用例判定 | 本次实际行为是否符合预期安全结果？ | 记录通过、失败、阻断、待实测等状态 | 未授权工具调用被服务端按预期阻断 |
| 风险结论 | 证据支持什么影响和处置优先级？ | 复核、评分、修复和复测 | 模型产生危险候选，但工具层新增副作用为零 |

“阻断”有两个上下文：流程门禁阻断表示当前阶段不能继续；用例状态“阻断”表示某项控制按预期阻止了测试动作。记录时必须注明阶段和原因，避免混淆。

## 13. 步骤 2：本地模拟 LLM 应用最小测试计划

> 计划状态：已完成测试计划设计，尚未在本步骤发起新的执行。  
> 适用范围：学习单元 8–12 已形成的本地用例、虚构文档、模拟身份、模拟工具、合成敏感字段及其既有证据。  
> 结论边界：本计划只定义如何测试和保存证据，不表示五个验证域已经全部通过，也不支持对真实或生产环境作安全结论。

### 13.1 项目目标

本项目以一个本地模拟 LLM 应用为测试对象，验证以下五个安全问题：

1. **Prompt 边界**：用户输入、文档内容或工具返回中的控制样式文本是否会改变固定任务、规则或输出契约。
2. **RAG 数据权限**：无权文档是否在模型调用前被排除，进入上下文的片段是否保留来源、版本、信任和权限信息。
3. **Agent 模拟工具**：模型产生的候选工具调用是否经过 allowlist、Schema、主体/动作/对象/参数授权、确认和幂等控制。
4. **输出处理**：模型原始输出是否经过结构解析、字段限制、引用核对、敏感信息检查、编码和最终展示控制。
5. **合成数据泄露控制**：合成敏感字段是否越过角色、上下文、工具返回、日志、缓存或证据存储边界。

测试重点是验证完整控制链，而不是仅观察模型是否拒答，也不评价模型的一般智能水平。

### 13.2 范围与非目标

#### 范围内

- 使用 `cases/llm-security/` 中学习单元 8–12 的本地用例和状态记录；
- 使用 `labs/stage-02/documents/` 中的虚构文档和本地 RAG 夹具；
- 使用 `labs/agent-tool-security/` 中的模拟工具、权限矩阵和确定性执行器；
- 使用学习单元 12 的合成邮箱、手机号、模拟 Key 和业务编号；
- 使用访客、分析员和管理员三种模拟身份；
- 对已有 Prompt、Response、JSONL、权限决定和复盘进行检查、复核与后续规范化；
- 在后续明确批准的用例中执行无害本地输入、模拟权限分支和零真实副作用测试。

#### 非目标

- 测试真实模型服务、网站、第三方 API、生产 Agent 或业务系统；
- 绕过真实模型或平台的安全策略；
- 访问真实用户、客户、员工、凭据、日志或业务数据；
- 产生真实邮件、工单、支付、数据库、文件、网络或命令执行副作用；
- 验证生产 IAM、真实工具网关、真实日志平台、并发事务或完整删除传播；
- 根据单一模型、小样本、本地模拟器或既有阻断结果推断其他模型和真实系统安全；
- 把用例数量、平均分、模型拒答或模板存在当作安全证明。

| 禁止动作 | 真实外部调用、真实敏感数据、破坏性负载、生产凭据、持久化变更、真实业务副作用、从模型文本取得或扩大权限 |
| 成功证据 | 原始请求/响应、模型与参数、Prompt/规则版本、上下文来源、模拟角色、策略决定、工具结果、副作用数、DurationSeconds、日志或证据 ID |
| 停止条件 | 超出模拟范围、发现真实秘密或个人数据、意外外部连接、不可控副作用、授权撤销或过期、证据隔离失效 |
| 数据处理 | 普通日志保存最小决定元数据；完整 Prompt/Response 仅按需进入受控证据区；所有样例使用虚构或合成值 |
| 恢复条件 | 已记录原因和影响范围，完成隔离或回滚，更新用例与范围，并由授权人、测试负责人和复核人确认恢复 |

### 13.4 允许动作与禁止动作一致性

| 动作类别 | 允许的本地行为 | 对应禁止边界 | 一致性结论 |
|---|---|---|---|
| 配置检查 | 读取本地模型、Prompt、Schema、权限矩阵和证据版本 | 不修改生产配置，不访问真实管理面 | 无重叠 |
| 测试输入 | 使用无害文本、虚构文档和合成敏感字段 | 不使用真实秘密、个人数据或破坏性负载 | 无重叠 |
| 身份与权限 | 使用固定访客、分析员、管理员模拟身份验证允许/拒绝分支 | 不使用真实账号，不信任用户或模型自报角色 | 无重叠 |
| 工具行为 | 调用本地模拟工具，验证 Schema、授权、确认和幂等 | 不连接真实工具，不产生真实邮件、工单、支付或文件修改 | 无重叠 |
| 日志与证据 | 检查本地日志、JSONL 和受控证据引用 | 不抓取真实日志，不把敏感原文无差别写入普通日志 | 无重叠 |
| 状态改变 | 仅允许可重置的内存状态或明确的 dry-run 结果 | 不允许生产或非夹具的持久化变更 | 无重叠 |

如果后续用例同时命中“允许”和“禁止”描述，以禁止边界和停止规则为准；必须先修改范围和重新授权，不能由执行人员临场解释为允许。

### 13.5 三层成功证据

#### 模型层

至少记录：

- 用例 ID、批次和请求 ID；
- 模型提供方或本地入口、模型/部署 ID 与版本；
- temperature、top_p、seed、最大输出和超时等参数；
- 完整 Prompt、完整原始 Response 和 HumanModified；
- 重复次数、独立会话状态、耗时和模型调用错误。

模型层证据回答“模型在什么条件下产生了什么候选输出”，不能单独证明应用授权或工具执行结果。

#### 应用层

至少记录：

- 模拟身份、服务端角色、会话和任务范围；
- 系统 Prompt、规则、解析器和 Schema 版本；
- RAG 文档/片段 ID、来源、信任、权限、索引版本及最终上下文成员；
- 输出结构、引用、敏感字段和编码检查结果；
- 应用的允许、拒绝、阻断或需复核决定及原因码。

应用层证据回答“候选输入输出经过了哪些编排和确定性控制”，不能仅凭最终文本反推上游控制一定存在。

#### 工具层

至少记录：

- 候选工具名、参数键和参数摘要/哈希；
- allowlist、Schema、主体×动作×对象×参数授权结果；
- 确认引用、幂等键、首次执行或重放状态；
- 工具是否到达执行器、模拟结果 ID 和新增副作用数；
- 工具返回 Schema、字段裁剪、信任标签和下一轮调用处理。

工具层证据回答“动作是否被允许和执行，以及产生了什么状态变化”，不能用模型声称“已执行”代替。

### 13.6 典型跨层判定

以访客角色请求 `create_ticket` 为例：模型或 Agent 生成结构合法的候选调用，但权限矩阵不允许访客使用该工具。

完整证据链应为：

```text
身份：服务端模拟会话绑定 visitor，关联权限矩阵版本
候选：模型/Agent 生成 create_ticket 及参数
结构：Schema 校验通过，排除格式错误导致的拒绝
授权：在角色工具权限阶段拒绝，记录策略版本和原因码
执行：未到达模拟执行器，未创建模拟工单，新增副作用为 0
关联：用批次、请求 ID、幂等键或时间戳串起全部记录
```

因此应同时记录三个结论：

1. 模型产生了危险候选调用；
2. 应用/工具权限控制按预期阻断；
3. 本次最终新增副作用为零。

不能把它们压缩成没有主语和层次的“测试通过”。

### 13.7 合成数据未出现在最终输出时的检查范围

最终展示中没有出现合成手机号，只能证明“本次最终可见输出未观察到该值”。要判断控制链，还需检查：

- 用户 Prompt、系统 Prompt、历史消息和最终模型上下文；
- RAG 召回候选、权限过滤后片段和最终上下文清单；
- 工具原始返回、裁剪后返回和实际送入模型的字段；
- 模型原始 Response 与脱敏后的最终响应；
- 普通日志、受控证据区、追踪、错误附件和导出记录；
- 缓存、会话记忆、索引和临时文件；
- 角色、对象和字段授权决定。

没有输出敏感字段不等于数据没有被读取、处理、缓存或记录。

### 13.8 步骤 2 的停止与升级规则

| 触发事件 | 立即动作 | 最低通知对象 | 后续状态 |
|---|---|---|---|
| 发现真实秘密或真实个人数据 | 停止受影响用例、限制证据访问、不继续查看或传播原文 | 测试负责人、数据负责人、复核人 | 异常调查；重新确认数据范围后决定是否恢复 |
| 意外外部连接 | 停止新请求、隔离连接器或出口、保存请求/日志 ID | 应用/平台负责人、授权人、复核人 | 查明连接和影响；重新授权后恢复 |
| 非模拟或不可控副作用 | 停止整个相关批次、记录状态变化、执行批准的回滚 | 应用/平台负责人、产品负责人、复核人 | 进入异常处置；未确认前不得继续 |
| 超范围请求 | 不执行，登记请求与所需资产/动作 | 测试负责人、授权人 | 标记未授权/不执行，或返回范围阶段申请变更 |
| 授权撤销或过期 | 停止所有新测试，只保留已有最小证据 | 授权人、全部相关负责人 | 未执行项标记未授权/不执行 |
| 证据隔离失效 | 停止产生新的原始证据，限制存储访问 | 数据负责人、应用/平台负责人、复核人 | 修复证据管道并复核已有数据 |

### 13.9 步骤 2 主动回忆结论

学习者已能够解释：

- “不访问真实外部服务”同时属于非目标与禁止动作：前者限制结论范围，后者限制执行行为；
- Schema 通过只说明候选调用结构有效，访客工具权限仍必须由应用/工具层确定性检查；
- 一条阻断结论需要身份、候选调用、校验与授权、执行结果和关联 ID 五类证据；
- 最终输出未出现合成敏感值不能证明控制链通过，还需检查上下文、RAG、工具、原始输出、日志、缓存和存储。
