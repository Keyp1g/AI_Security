# 学习单元 12：训练数据泄露与隐私风险（理论部分）

> 文档定位：学习单元 12 在实验执行前形成的理论快照，用于保留概念学习证据。
> 当前状态：学习单元 12 的完整成果已验收；最新状态与证据入口见 [`../docs/learning-units.md`](../docs/learning-units.md)。本文件不回填后续实验结果。

## 1. 核心判断

隐私风险不能只根据模型输出分类。调查时应依次确认：

1. 数据最初从哪里进入系统；
2. 数据在哪个阶段越过角色、会话、用途或展示边界；
3. 哪个组件本应阻止；
4. 哪些证据能让其他人复核。

模型复述当前 Prompt 中的内容，只能说明本次上下文足以解释该输出。若要判定上下文泄露，还需证明字段受保护、接收者无权查看或系统策略禁止完整展示。该现象本身不能证明数据来自训练集。

证据状态应分为：

- **风险信号**：出现值得调查的现象，但来源或授权边界尚未查清；
- **已证实泄露**：证据表明受保护数据跨越了不允许的边界；
- **待进一步验证**：异常现象存在，但仍需排除上下文、检索、工具、缓存、日志或随机生成等其他解释。

## 2. 九个核心术语

| 术语 | 定义与触发条件 | 关键验证与结论边界 |
| --- | --- | --- |
| 训练数据泄露 | 敏感内容参与预训练或微调，模型行为暴露或允许推断相关信息 | 排除 Prompt、历史、RAG、工具、缓存和日志等来源；单次或重复输出不能独立证明训练来源 |
| 成员推理 | 判断某条记录是否属于训练集 | 需要成员/非成员对照、统计指标、基线和误差分析；单个高置信回答不足以证明成员身份 |
| 模型反演 | 根据输出、置信信息或多次查询，重建输入特征、敏感属性或近似内容 | 需要与受控真值比较并排除其他数据源；貌似真实的资料可能只是幻觉 |
| 上下文泄露 | 当前 Prompt、系统提示、历史消息或 RAG 片段中的受保护数据越过允许边界 | 核查字段分类、接收者权限、会话边界和输出策略；模型复述不必然构成泄露 |
| 日志泄露 | 请求、响应、错误、调试信息或元数据被过度记录，或被不适当主体读取 | 检查真实日志字段、访问权限、导出路径和保留配置；界面遮盖不能证明日志安全 |
| 工具返回泄露 | 数据库、搜索、CRM 或业务 API 返回了超出任务或角色所需的字段 | 关联工具请求、原始响应、裁剪决定、模型请求和最终输出；首要控制通常在工具端和模型调用前 |
| 脱敏 | 删除、遮盖、泛化、标记化或不可逆转换敏感字段，使数据符合当前用途 | 遮盖不等于匿名化，还需检查角色、展示位置、可恢复性和重新识别风险 |
| 数据最小化 | 只采集、检索、传输、交给模型并保存完成任务所必需的数据 | 事后输出过滤不能替代上游最小化；未进入模型的数据更难传播到缓存和日志 |
| 保留周期 | 规定数据保存期限、删除时点、延期例外和删除验证 | 主库删除不等于全链路删除，还需覆盖副本、索引、缓存、日志、备份和人工反馈数据 |

成员推理与模型反演的核心区别是：前者问“这条记录是否参加过训练”，后者问“能否从模型行为恢复输入特征或敏感属性”。

## 3. 四类泄露面的对照

| 泄露面 | 数据来源 | 发生阶段 | 典型证据 | 责任组件 | 首要控制 | 复测方式 |
| --- | --- | --- | --- | --- | --- | --- |
| 训练数据 | 预训练或微调语料 | 数据准备、训练及后续推理 | 受控条件下出现稳定的样本相关行为，并已排除其他来源 | 数据治理、训练流程、模型提供方 | 数据清洗、去重、用途审查和隐私评估 | 成员/非成员对照、重复查询、统计分析和来源调查 |
| 上下文 | 当前 Prompt、系统提示、历史消息或 RAG 片段 | 请求组装和模型输出 | 受保护值存在于本次上下文，并被无权主体或禁止位置看到 | 会话管理、Prompt/RAG 编排、输出审查 | 输入最小化、会话隔离和模型前权限过滤 | 固定上下文，改变角色、会话或字段授权并比较结果 |
| 日志 | 请求、响应、错误、调试信息或审计元数据 | 记录、监控、排障和导出 | 普通日志出现未遮盖字段，或无权账号能够读取日志 | 产生日志的应用、日志平台和运维体系 | 日志最小化、脱敏、访问控制和保留周期 | 触发合成事件后检查日志出口、读取权限和到期删除 |
| 工具返回 | 数据库、CRM、搜索或业务 API 响应 | 工具调用、返回处理和模型再规划 | 原始响应含多余字段，字段进入模型请求、输出、日志或缓存 | 工具网关、业务 API、应用编排 | 查询授权、数据最小化、响应 Schema 或字段白名单 | 固定任务，改变角色和请求字段，追踪原始响应至最终输出 |

## 4. 同一字段在不同数据面中的意义

以虚构邮箱 user01@example.invalid 为例：

- **训练数据场景**：该值存在于已知的受控训练集合，测试成员与非成员行为是否存在稳定差异。测试 Prompt 不能直接提供该值，否则无法归因。
- **上下文场景**：该值由当前输入、历史或 RAG 片段进入请求，随后越过角色、会话或展示边界。这里验证请求组装和授权，不验证训练记忆。
- **日志场景**：用户界面已经遮盖邮箱，但普通调试日志仍保存完整值。界面控制通过不能抵消日志侧失效。
- **工具返回场景**：任务只需订单状态，工具却返回完整邮箱。即使模型没有显示它，数据最小化也已经失效，还需检查模型请求、日志、缓存和会话记忆。

## 5. 关键边界

### RAG 数据不自动等于训练数据

RAG 文档通常在推理阶段动态进入上下文。只有数据实际参与了预训练或微调，才进入训练数据泄露的调查范围。

### 一次事件可以跨越多个泄露面

工具多返回字段可能是根因；字段随后进入模型请求、日志或最终响应，则说明风险继续传播。测试记录应分别保存工具原始响应、裁剪后响应、实际模型请求、日志和最终输出。

### “模型没有输出”不等于“没有风险”

非必要字段可能已经进入模型服务、追踪系统、缓存、会话记忆或日志。输出过滤是最后一道兜底，不能替代查询授权、字段最小化和模型前裁剪。

### 重复输出仍不足以归因训练来源

模型重复输出某个未出现在用户 Prompt 中的值，只会增强风险信号。调查还需排除系统提示、历史消息、RAG、工具返回、会话记忆、缓存、应用预置样例、日志回注、公开资料、提示诱导和随机生成，再通过受控对照与统计分析评估训练来源。
