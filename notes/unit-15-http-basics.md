## 1. 教材与本步骤边界

总教材将 HTTP/HTTPS 列为网络安全基础，并强调 AI 应用层负责接收用户请求，再将数据传递到模型、RAG、工具或其他后端组件。教材没有系统展开 HTTP 报文、方法和状态管理细节，因此本文按照学习单元要求补充这些基础。

本文区分三类内容：教材明确内容、步骤 1 的 HTTP 基础补充，以及后续待实测的浏览器观察和本地实验。

## 2. 最小请求与响应模型

```text
浏览器/客户端
  -> 请求行 + Headers + 可选 Body
  -> 服务端

浏览器/客户端
  <- 状态码 + Headers + 可选 Body
  <- 服务端
```

HTTP/1.1 常以文本形式展示请求行、Header、空行和 Body。HTTP/2、HTTP/3 在线路上使用帧，但逻辑上仍可用“请求信息 + Header + Body”和“状态 + Header + Body”理解。

### 2.1 请求示例

```http
POST /api/chat?workspace=demo HTTP/1.1
Host: ai.example.invalid
Content-Type: application/json
Accept: application/json
Cookie: session_id=[REDACTED]
X-Request-ID: req-015-001

{"message":"总结公开文档","document_scope":"internal"}
```

### 2.2 响应示例

```http
HTTP/1.1 302 Found
Location: /login?next=%2Fapi%2Fchat
Set-Cookie: session_id=deleted; Max-Age=0; HttpOnly; Secure; SameSite=Lax
Cache-Control: no-store
Content-Length: 0
```

该响应强烈支持“当前会话无效、过期或需要重新认证”的推断：`Location` 指向登录入口，`Set-Cookie` 要求立即删除原 Session Cookie。最终原因仍应由认证决定码或服务端日志确认。

## 3. HTTP 核心术语

| 术语 | 用自己的话解释 | 安全意义 |
|---|---|---|
| URL | 定位网络资源的地址，可包含协议、主机、端口、路径、查询参数和片段 | 查询串容易进入历史、代理和访问日志，不应承载密码或长期令牌 |
| 域名/主机 | 客户端准备连接和请求的网络主机名称 | `Host` 来自请求；服务端仍需校验允许的主机，不能由其决定用户权限 |
| 路径 | 主机下资源或接口的位置，例如 `/api/chat` | 路径中的对象 ID 仍需执行对象级授权，能猜到路径不等于有权访问 |
| 查询参数 | URL 中 `?` 后的键值对，例如 `page=2` | 通常由客户端控制，需校验类型、长度和范围；敏感值可能被多处记录 |
| HTTP 方法 | 表达客户端希望对资源执行的操作语义 | 方法名称不是授权控制；服务端必须独立检查主体、对象和动作权限 |
| 请求行 | HTTP/1.1 中由方法、请求目标和协议版本组成 | 可识别客户端想访问的路径和操作，但不能据此信任身份或权限 |
| 请求头 | 描述格式、凭据、来源、缓存和客户端能力等元数据 | `Cookie`、`Authorization` 等值可能是凭据，普通日志只保留必要存在性或脱敏值 |
| 请求体 | 空行后的实体内容，常为 JSON、表单或文件 | 即使使用 HTTPS，服务端、代理和日志仍可能接触明文；必须做 Schema 和业务校验 |
| 状态行/状态码 | 响应对本次 HTTP 处理结果的分类 | `200` 只表示 HTTP 层处理成功，不证明认证、授权或业务安全正确 |
| 响应头 | 描述响应格式、缓存、Cookie、重定向等元数据 | `Set-Cookie`、`Location` 和缓存策略会影响会话、跳转与数据留存 |
| 响应体 | 服务端返回的 JSON、HTML、文本或文件 | 合法 JSON 不等于安全结果；还需检查字段、引用、隐私和安全渲染 |
| Cookie | 浏览器按规则保存并随匹配请求发送的小型数据 | 可能包含 Session ID；应关注 `HttpOnly`、`Secure`、`SameSite` 和生命周期 |
| Session | 服务端用于维持登录身份或连续状态的会话机制 | Session ID 相当于凭据；存在 Cookie 不等于会话有效，必须由服务端验证 |
| 缓存 | 客户端或中间节点复用先前响应的机制 | 用户或租户相关响应若被错误共享缓存，可能造成跨用户数据泄露 |
| 重定向 | 服务端要求客户端继续访问另一个位置 | 需防开放重定向和敏感参数泄露；`302` 本身不能证明原业务已执行 |
| HTTPS | 在 TLS 保护下传输 HTTP | 提供传输机密性、完整性和服务端身份验证；不保护落入日志、备份或应用内存的数据 |
| 幂等性 | 相同请求执行多次，预期主要资源最终状态与执行一次相同 | 用于设计重试和防重，但不表示无副作用、无日志或没有风险 |
| 安全方法 | 规范上只读取，不要求改变目标资源状态的方法 | “安全”是方法语义，不表示接口没有越权、泄露或拒绝服务风险 |

## 4. 常见请求头与响应头

| Header | 主要含义 | 使用边界 |
|---|---|---|
| `Content-Type` | Body 实际采用的媒体类型 | 服务端应限制允许的类型，并按同一解析规则处理 |
| `Accept` | 客户端期望的响应媒体类型 | 不能代替输出编码和内容安全审查 |
| `Authorization` | 客户端提交的认证凭据 | 必须验证签名、签发者、受众、期限和绑定；不得原样进入普通日志 |
| `Cookie` | 客户端发送的 Cookie | 原始内容由客户端提交；服务端验证会话后才能得到可信主体 |
| `Set-Cookie` | 服务端要求客户端保存或删除 Cookie | 检查生命周期以及 `Secure`、`HttpOnly`、`SameSite` |
| `Location` | 重定向位置或新资源位置 | 目标需限制，避免开放重定向和秘密进入 URL |
| `Cache-Control` | 控制响应存储和复用方式 | `no-store` 表示不要存储；`no-cache` 表示复用前必须重新验证 |
| `Origin` | 浏览器页面发起请求的源 | 可辅助 CORS/CSRF 判断，但不是身份凭据 |
| `ETag` | 资源版本的验证标识 | 可用于条件请求，值不应编码用户秘密 |
| `X-Request-ID` | 关联一次请求链路的标识 | 客户端值需校验或在可信入口重建，不能作为身份或授权凭据 |

## 5. 六种 HTTP 方法

| 方法 | 语义 | 典型用途 | 安全方法 | 幂等 | 常见误用风险 |
|---|---|---|---:|---:|---|
| `GET` | 获取资源表示 | 页面、搜索、读取 API 数据 | 是 | 是 | 敏感查询值进入日志；错误实现为有副作用操作；对象级越权 |
| `POST` | 提交数据，由目标资源决定如何处理 | 创建子资源、提交表单、触发动作 | 否 | 不保证 | 重复创建、重复扣款或重复工具调用；CSRF；输入校验不足 |
| `PUT` | 创建或整体替换确定 URI 的资源 | 保存完整配置、替换资源 | 否 | 是 | 覆盖遗漏字段、批量赋值、对象级越权 |
| `PATCH` | 对资源执行局部修改 | 修改部分资料或状态 | 否 | 不保证 | 字段级越权、自我提权、受保护字段被修改 |
| `DELETE` | 删除目标资源 | 删除记录或撤销对象 | 否 | 是 | 删除他人对象、缺少确认或恢复机制、不可逆副作用 |
| `OPTIONS` | 查询支持的方法或进行 CORS 预检 | 浏览器跨源预检、能力查询 | 是 | 是 | 把 CORS 允许误认为业务授权；暴露不必要能力 |

幂等不等于没有副作用。例如重复 `DELETE` 可能产生多条审计日志，但目标资源的最终状态仍然是“不存在”。安全方法也不等于没有安全风险；`GET` 仍可能发生数据泄露、对象级越权或资源耗尽。

## 6. 状态码与判断边界

| 状态码 | 常见含义 | 不能据此单独证明什么 |
|---|---|---|
| `200 OK` | 请求已处理并返回响应 | 不能证明对象授权、数据正确或输出安全 |
| `201 Created` | 创建了资源 | 不能证明创建动作符合业务和权限规则 |
| `204 No Content` | 请求成功，无响应体 | 不能证明服务端没有产生额外副作用 |
| `302 Found` | 临时重定向 | 不能证明原操作已执行；历史客户端常把后续请求改为 `GET` |
| `303 See Other` | 使用 `GET` 获取另一个资源 | 不能替代对原提交结果的业务证据 |
| `307/308` | 重定向并保持原方法和 Body | 目标仍需信任边界和凭据泄露检查 |
| `400 Bad Request` | 格式或参数不符合要求 | 不代表认证失败 |
| `401 Unauthorized` | 缺少有效认证凭据 | 不说明某个具体对象是否存在 |
| `403 Forbidden` | 服务端拒绝当前操作 | 不应泄露不必要的对象或策略细节 |
| `404 Not Found` | 资源不存在，或服务端选择隐藏其存在性 | 不能反向证明授权逻辑正确 |
| `409 Conflict` | 与当前资源状态冲突 | 不能替代幂等和并发控制证据 |
| `429 Too Many Requests` | 触发速率限制 | 不证明认证、授权或输入校验有效 |
| `500` | 服务端内部错误 | 错误体不应泄露堆栈、路径、密钥或内部 Prompt |
| `502/503/504` | 上游异常、暂不可用或超时 | 不能只凭状态码定位是模型、RAG、工具还是网关故障 |

`401` 通常表示凭据缺失、失效或验证失败；`403` 通常表示身份已知但操作被拒绝。对无权访问的对象统一返回 `404` 可以减少资源枚举，但服务端审计仍应记录真实拒绝原因。

## 7. Cookie、Session、缓存与重定向

### 7.1 Cookie 与 Session

Cookie 存在客户端，Session 通常由服务端维护。典型登录流程是：服务端验证凭据后创建 Session，通过 `Set-Cookie` 将不可预测的 Session ID 发给浏览器；后续浏览器发送该 Cookie，服务端验证它并恢复主体及会话状态。

客户端提交 Cookie 不等于服务器可以直接相信其内容。可信身份必须来自服务端对 Session 或令牌的验证结果。Session 可能存储在内存、数据库、缓存或分布式会话服务中。

### 7.2 缓存

- `no-store`：浏览器和中间缓存不应存储该响应。
- `no-cache`：可以存储，但每次复用前必须向源服务器重新验证。
- 缓存指令不阻止服务端访问日志、WAF、APM 或审计系统记录请求；日志需要独立脱敏和保留策略。

### 7.3 重定向

- `301/302`：永久或临时跳转；旧有客户端行为可能把 `POST` 改成 `GET`。
- `303`：明确让客户端使用 `GET` 获取另一个资源，适合表单提交后的结果页。
- `307/308`：保持原方法和请求体。

重定向后的请求不能自动证明原请求已成功执行，应结合业务对象、幂等键、下游调用 ID 和服务端日志判断。

## 8. AI 应用中的 HTTP 映射

| HTTP 位置 | AI 应用示例 | 主要控制点 |
|---|---|---|
| 请求体 | `message`、对话设置、工具候选参数 | Schema、类型/长度、来源标记；用户文本不能产生权限 |
| Cookie/Authorization | Session ID 或访问令牌 | 服务端验证后取得主体、租户和会话状态 |
| 查询参数或请求体范围 | workspace、候选 `document_scope`、分页和排序 | 仅代表客户端访问意图；最终范围取“请求范围 ∩ 服务端授权范围” |
| RAG 后端请求 | query、TopK、允许文档范围 | 模型调用前执行对象级 ACL、缓存权限绑定和上下文最小化 |
| 模型适配层 | Prompt、模型版本、参数、原始响应 | 保留可复测配置；模型输出是不可信候选数据 |
| Agent 工具 API | 工具名、动作、对象和结构化参数 | allowlist、严格 Schema、主体×动作×对象×参数授权、确认和幂等 |
| 响应体 | answer、status、citations、结构化字段 | Schema、引用支持、隐私、Markdown/HTML 安全渲染和发布决定 |
| 关联 Header/字段 | `request_id`、`run_id`、`call_id` | 连接网关、RAG、模型、工具和输出审查的最小审计证据 |

最小服务端处理顺序：

```text
HTTP 入口
→ 认证与会话验证
→ 请求解析、Schema、大小和类型检查
→ 服务端租户及对象授权
→ RAG 模型前 ACL 与上下文最小化
→ 模型生成候选结果
→ 工具 Schema、授权、确认与幂等检查
→ 引用、隐私和安全渲染审查
→ 关联审计
→ 返回结构化响应
```

## 9. 客户端声明与服务端事实

客户端可以提交用户问题、格式偏好、分页、候选 workspace、候选文档范围和工具参数。它们都只是请求数据。必须由服务端验证或计算认证主体、租户、角色、对象 ACL、最终文档范围、工具权限、配额、策略决定和审计主体。

```text
JSON 可解析
≠ Schema 合法
≠ 字段可修改
≠ 对象可访问
≠ 动作已授权
≠ 业务状态允许变化
```

```text
HTTP 200
≠ 输出格式合法
≠ 业务成功
≠ 安全控制正确
```

## 10. 敏感信息记录边界

普通学习笔记和日志不记录完整的 Cookie、Session ID、`Authorization`、API Key、CSRF Token、密码、个人信息、真实用户/租户/文档标识、敏感 Prompt/RAG 正文/工具返回或可关联真实个人的请求 ID。

记录时保留字段名、是否存在、长度、必要属性和遮盖后的占位值，例如：

```text
Cookie: session_id=[REDACTED]
Authorization: Bearer [REDACTED]
USER_ID_FICTIONAL
DOC_ID_FICTIONAL
```

本笔记示例中的 `.invalid` 域名、`workspace=demo`、`req-015-001`、公开文档消息和 `session_id=deleted` 均为虚构或非秘密教学值，可以保留。`document_scope="internal"` 也可保留，但必须明确它只是客户端声明，不是授权证据。
