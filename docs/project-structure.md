# 项目结构

## 目录职责

| 路径 | 职责 | 典型命名 |
|---|---|---|
| `plan/` | 总路线和每个学习单元的计划、验收要求 | `unit-NN.md` |
| `notes/` | 概念、阅读和机制笔记 | `unit-NN-topic.md`、`stage-NN-topic.md` |
| `labs/` | 实验说明、输入夹具和可运行脚本 | `unit-NN-topic.md`、`run-unitNN-topic.ps1` |
| `cases/` | 结构化安全测试用例和作品用例库 | `unit-NN-topic.md` 或主题名 |
| `reports/` | 原始运行证据、学习单元复盘和阶段总结 | `unit-NN-topic.*`、`stage-NN-topic.md` |
| `tools/` | 跨学习单元复用的评测器和辅助工具 | 主题化名称 |
| `docs/` | 领域说明、成果注册表、结构约定和架构决策 | 语义化名称 |
| `路线/` | 学习阶段和作品路径图 | 内容语义名称 |

## 身份与命名

- `unit-NN` 是学习进度、验收和发布的唯一身份。
- `stage-NN` 是课程结构身份，不代表自然周。
- 文件名中的两位编号保持稳定；正式用例 ID（如 `LLM-012-01`）独立于文件名，不随目录整理改变。
- 机器可读 JSON/JSONL 是原始证据。可以迁移路径，但不得为了统一措辞改写已记录内容。

## 学习单元证据包

一个完整学习单元通常包含：

1. `plan/unit-NN.md`：要求和验收门槛；
2. `notes/unit-NN-*.md`：概念和机制；
3. `labs/unit-NN-*` 或 `labs/run-unitNN-*`：实验设计、夹具和运行器；
4. `cases/**/unit-NN-*.md`：人工复核与结构化用例；
5. `reports/unit-NN-*`：原始记录和复盘；
6. `docs/learning-units.md`：公开状态与证据入口。

并非每个学习单元都必须机械地产生全部文件；只要现有成果承载同等证据，注册表应引用实际文件，避免重复文档。

## 发布边界

- `.gitignore` 默认忽略未验收的 `unit-*` 和 `stage-*` 成果，再显式允许已经确认公开的文件。
- `.scratch/`、本地模型、教材副本、PDF、编辑器日志、个人草稿和 `labs/server-security/` 保持本地。
- README 中出现的成果链接必须同时存在于发布白名单；禁止链接只在本地存在的依赖。
- 上线前验证相对链接、脚本语法、JSON/JSONL 可解析性、敏感信息和 Git 精确暂存范围。
