# ADR-0001：使用学习单元作为唯一进度身份

- 状态：已接受
- 日期：2026-10-13

## 背景

仓库最初以自然日和周次组织计划、文件名、README 导航与 `.gitignore` 发布规则。学习内容后来改为 6 个阶段、42 个学习单元，但旧身份仍同时存在，导致同一成果具有多套名称，计划完成状态、公开状态和文件路径容易不一致。

学习任务的实际耗时并不稳定。一个主题可能跨多个自然日完成，也可能因补证返工；用日期身份会把时间安排误当成验收状态。

## 决策

1. 使用 `unit-NN` 作为学习进度、验收和发布的唯一身份。
2. 使用 `stage-NN` 表示课程结构，不把阶段解释为自然周。
3. 当前成果路径统一迁移到 `unit-NN-*` 或 `stage-NN-*`；README、索引、脚本和发布规则不再维护 Day/Week 兼容入口。
4. README 只保留项目入口和当前状态，完整成果注册表由 `docs/learning-units.md` 承担。
5. 总学习计划只描述稳定路线与验收规则；服务器配置、工具版本和运行态待办留在本地环境材料中。
6. JSON/JSONL 原始证据内容保持不变；路径迁移不得重写已记录事实。

## 结果

- 一个学习单元只有一个 canonical 身份，导航、计划、成果和发布边界可以直接对应。
- 路径迁移会产生一次较大的 Git rename，但后续不再承担双命名维护成本。
- 个人自然时间线与公开技术证据分离，更符合公开隐私最小化原则。
- 外部旧链接不设置仓库内兼容副本；Git 历史仍可追溯迁移前文件。

## 验证

- 活跃 Markdown 和脚本不使用 Day/Week 表示进度身份。
- README 中的成果入口均指向存在且允许发布的文件。
- `.gitignore` 默认阻止后续学习单元进入发布范围，并显式允许已验收的学习单元 12 证据包。
